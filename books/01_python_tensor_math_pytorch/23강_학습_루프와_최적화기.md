# 23강. 학습 루프와 최적화기
## 이번 강에서 배우는 내용

- `zero_grad → forward → loss → backward → step` 순서를 암기하지 않고 이해한다.
- SGD와 Adam의 차이를 직관적으로 설명한다.
- 학습률(learning rate)이 학습에 미치는 영향을 실험으로 확인한다.
- 작은 회귀/분류 모델을 끝까지 학습시키는 스크립트를 작성한다.

## 왜 중요한가?
모델을 정의만 하고 끝내면 아무 지식도 학습되지 않는다. 학습이란 다음의 반복이다.

```text
현재 파라미터로 예측
  → 틀린 정도(Loss) 측정
    → 기울기 계산
      → 파라미터를 조금 수정
        → 다시 예측 ...
```

이 반복을 코드로 고정한 것이 **학습 루프(training loop)**이다.  
파라미터를 “조금 수정”하는 규칙을 구현한 객체가 **Optimizer(최적화기)**이다.

LLM Pretraining도 본질적으로 같은 루프다. 다만 배치가 토큰이고, Loss가 next-token cross entropy이며, 스케줄러·혼합 정밀도·분산 통신이 덧붙는다. 뼈대는 이번 강의에서 끝낸다.

## 선수 개념
1. **Loss** — 예측과 정답의 차이를 하나의 스칼라로 만든 것 (제13강)
2. **Gradient** — Loss를 파라미터로 미분한 방향 (제12강)
3. **Autograd** — `loss.backward()`가 `.grad`를 채움 (제20강)
4. **parameters()** — Optimizer에 넘길 텐서 목록 (제21강)
5. **DataLoader** — 배치 공급 (제22강)

## 핵심 개념
### 3.1 표준 학습 스텝 다섯 단계

한 배치를 처리하는 표준 순서는 다음과 같다.

```text
1. optimizer.zero_grad()
2. logits = model(xb)          # forward
3. loss = criterion(logits, yb)
4. loss.backward()             # Autograd
5. optimizer.step()            # 파라미터 갱신
```

각 단계의 의미:

| 단계 | 하는 일 | 빼먹으면 |
|---|---|---|
| `zero_grad` | 이전 배치의 `.grad`를 비움 | 기울기가 누적되어 갱신량이 폭주 |
| forward | 현재 파라미터로 예측 | 학습 자체가 없음 |
| loss | 스칼라 목적함수 계산 | backward 불가 |
| backward | 각 파라미터에 `.grad` 저장 | step이 갱신할 방향 없음 |
| step | $\theta \leftarrow \theta - \Delta$ | 파라미터 불변 |

PyTorch는 기본적으로 Gradient를 **누적(accumulate)**한다. 그래서 매 스텝 시작에 `zero_grad()`가 필요하다. (나중에 Gradient Accumulation을 배울 때는 의도적으로 여러 번 backward 후 한 번 step 한다.)

### 3.2 Optimizer란 무엇인가

**Optimizer(최적화기)**는 파라미터와 학습 규칙을 받아, `.grad`를 이용해 파라미터 값을 갱신하는 객체이다.

```python
optimizer = torch.optim.SGD(model.parameters(), lr=0.01)
# 또는
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3)
```

공통 인터페이스:

- `zero_grad()` — 기울기 초기화
- `step()` — 파라미터 갱신

Optimizer는 모델 구조 자체를 모른다. “갱신할 텐서 목록”과 “규칙”만 안다.

### 3.3 SGD

**SGD(Stochastic Gradient Descent, 확률적 경사하강법)**의 기본형은 다음과 같다.

$$

\theta \leftarrow \theta - \eta \nabla_\theta L_B(\theta)

$$

- $\eta$: **learning rate(학습률)**
- $L_B$: 미니배치 손실

모멘텀을 쓰면 이전 속도 항을 섞어 진동을 줄이고 가속을 돕는다.

$$

\begin{aligned}
v &\leftarrow \mu v + \nabla_\theta L_B \\
\theta &\leftarrow \theta - \eta v
\end{aligned}

$$

직관: “미끄러운 경사로에서 관성으로 내려가기”.

### 3.4 Adam

**Adam(Adaptive Moment Estimation)**은 파라미터마다 학습률을 적응적으로 조절하는 최적화기다. 1차 모멘트(기울기 평균)와 2차 모멘트(기울기 제곱 평균)를 함께 사용한다.

직관만 남기면:

- 기울기가 자주·크게 흔들리는 파라미터는 업데이트를 작게
- 기울기가 안정적인 파라미터는 업데이트를 상대적으로 크게

딥러닝 실무와 LLM 학습에서 Adam 또는 **AdamW**(가중치 감쇠 방식이 다른 변형)가 매우 흔하다. 수식 전체를 외울 필요는 아직 없다. “SGD의 고정 보폭” vs “적응 보폭” 차이만 잡자.

### 3.5 Learning Rate

**Learning rate(학습률, $\eta$)**는 한 스텝에 파라미터를 얼마나 옮길지 정하는 비율이다.

| 학습률 | 증상 |
|---|---|
| 너무 큼 | Loss가 폭발하거나 진동 |
| 너무 작음 | Loss가 거의 안 줄어듦 |
| 적절 | 초반 감소 후 완만히 수렴 |

LLM 학습에서는 학습률을 일정하게 두지 않고 **Scheduler**로 워밍업 후 감쇠시키는 경우가 많다. (3권) 지금은 고정 학습률로 루프를 완성하는 것이 목표다.

### 3.6 train()과 eval()

`model.train()`과 `model.eval()`은 Dropout·BatchNorm 같은 층이 **학습 모드/평가 모드** 중 어디로 동작할지 바꾼다.

지금 당장 Dropout을 쓰지 않아도, 루프를 다음과 같이 습관화한다.

```python
model.train()
for xb, yb in train_loader:
    ...

model.eval()
with torch.no_grad():
    for xb, yb in val_loader:
        ...
```

`torch.no_grad()`는 평가 시 그래프 구축을 막아 메모리와 속도를 아낀다.

## 직관적으로 이해하기
산을 내려가는 등산객으로 비유한다.

- **Loss**는 현재 고도
- **Gradient**는 “가장 가파르게 올라가는 방향” (그래서 반대로 간다)
- **Learning rate**는 보폭
- **SGD**는 매 순간 기울기만 보고 같은 보폭으로 이동
- **Adam**은 지형에 따라 발걸임을 조절하는 숙련 등산객
- **zero_grad**는 이전 발자국 메모를 지우는 것
- **step**은 실제로 발을 옮기는 것

한 배치 = 안개가 낀 상태에서 주변 지형만 보고 한 걸음.  
여러 배치를 반복하면 전체 산의 평균 경사에 가까워진다.

## 수학적으로 이해하기
지도 학습에서 배치 손실

$$

L_B(\theta) = \frac{1}{|B|}\sum_{i\in B}\ell(f_\theta(x_i), y_i)

$$

에 대해 Autograd가 $\nabla_\theta L_B$를 계산한다. SGD라면

$$

\theta_{t+1} = \theta_t - \eta \nabla_\theta L_B(\theta_t)

$$

회귀에서 $\ell$이 MSE이면

$$

\ell(\hat{y}, y) = (\hat{y}-y)^2

$$

분류에서 흔히 쓰는 Cross Entropy는 2권 Softmax/Cross Entropy 강의에서 본격적으로 다룬다. 이번 강의 실습은 MSE 또는 `CrossEntropyLoss`를 “도구로” 사용한다.

## 작은 숫자로 직접 계산하기
파라미터 하나 $\theta=2.0$, 기울기 $g=0.5$, 학습률 $\eta=0.1$인 SGD 한 스텝:

$$

\theta \leftarrow 2.0 - 0.1 \times 0.5 = 1.95

$$

같은 상황에서 학습률이 $2.0$이면

$$

\theta \leftarrow 2.0 - 2.0 \times 0.5 = 1.0

$$

보폭이 크면 빨리 움직일 수도 있지만, 방향을 조금만 잘못 추정해도 멀리 튕긴다. 배치 Gradient는 추정치이므로, 큰 $\eta$는 위험하다.

`zero_grad`를 빼먹고 두 번 backward하면 `.grad`가 $0.5+0.5=1.0$이 되어

$$

\theta \leftarrow 2.0 - 0.1 \times 1.0 = 1.9

$$

처럼 **의도치 않은 누적**이 발생한다.

## 코드로 구현하기 — 완전한 학습 루프
```python
# train_loop_demo.py
import torch
import torch.nn as nn
from torch.utils.data import TensorDataset, DataLoader

class TinyMLP(nn.Module):
    def __init__(self):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(2, 16),
            nn.ReLU(),
            nn.Linear(16, 1),
        )

    def forward(self, x):
        return self.net(x)

def make_data(n=256, seed=0):
    g = torch.Generator().manual_seed(seed)
    x = torch.randn(n, 2, generator=g)
    y = (2 * x[:, 0] - 0.5 * x[:, 1]).unsqueeze(1)
    y = y + 0.05 * torch.randn(n, 1, generator=g)
    return x, y

def main():
    torch.manual_seed(0)
    x, y = make_data()
    loader = DataLoader(TensorDataset(x, y), batch_size=32, shuffle=True)

    model = TinyMLP()
    criterion = nn.MSELoss()
    optimizer = torch.optim.Adam(model.parameters(), lr=1e-2)

    model.train()
    for epoch in range(1, 21):
        total = 0.0
        count = 0
        for xb, yb in loader:
            optimizer.zero_grad()
            pred = model(xb)
            loss = criterion(pred, yb)
            loss.backward()
            optimizer.step()

            total += loss.item() * xb.size(0)
            count += xb.size(0)

        print(f"epoch {epoch:02d} | train MSE={total / count:.4f}")

if __name__ == "__main__":
    main()
```

예상 경향:

```text
epoch 01 | train MSE=...
epoch 05 | train MSE=...  (감소)
...
epoch 20 | train MSE=0.01대 또는 그 근처
```

절대 숫자는 시드·초기화에 따라 달라진다. **감소 추세**가 중요하다.

## PyTorch로 구현하기 — SGD vs Adam 비교
```python
def train_with_optim(optim_name: str, lr: float, epochs: int = 30):
    torch.manual_seed(0)
    x, y = make_data()
    loader = DataLoader(TensorDataset(x, y), batch_size=32, shuffle=True)
    model = TinyMLP()
    criterion = nn.MSELoss()

    if optim_name == "sgd":
        optimizer = torch.optim.SGD(model.parameters(), lr=lr)
    elif optim_name == "adam":
        optimizer = torch.optim.Adam(model.parameters(), lr=lr)
    else:
        raise ValueError(optim_name)

    history = []
    model.train()
    for _ in range(epochs):
        total = 0.0
        n = 0
        for xb, yb in loader:
            optimizer.zero_grad()
            loss = criterion(model(xb), yb)
            loss.backward()
            optimizer.step()
            total += loss.item() * xb.size(0)
            n += xb.size(0)
        history.append(total / n)
    return history
```

같은 에폭에서 `SGD(lr=0.05)`와 `Adam(lr=0.01)`의 Loss 곡선을 비교해 보면, 문제·학습률에 따라 승자가 달라진다. “항상 Adam”이 답은 아니지만, 기본 실험에서 Adam이 튜닝 부담이 적은 경우가 많다.

학습률만 바꾼 실험도 필수다. `Adam(lr=1.0)`처럼 극단값을 주면 Loss가 `nan`이 되는 장면을 직접 보는 것이 좋다.

## 수식 보강 — SGD · 모멘텀 · Adam

일반 SGD 업데이트:

$$
\theta_{t+1} = \theta_t - \eta\, \nabla_\theta L_{\mathcal{B}}(\theta_t)
$$

모멘텀 SGD:

$$
\mathbf{m}_{t+1} = \mu\, \mathbf{m}_t + \nabla_\theta L_{\mathcal{B}}(\theta_t)
$$

$$
\theta_{t+1} = \theta_t - \eta\, \mathbf{m}_{t+1}
$$

Adam은 1차·2차 모멘트의 편향 보정을 씁니다 ($\beta_1,\beta_2\in(0,1)$).

$$
\begin{aligned}
\mathbf{m}_{t+1} &= \beta_1 \mathbf{m}_t + (1-\beta_1)\mathbf{g}_t \\
\mathbf{v}_{t+1} &= \beta_2 \mathbf{v}_t + (1-\beta_2)\mathbf{g}_t^{\odot 2} \\
\hat{\mathbf{m}} &= \frac{\mathbf{m}_{t+1}}{1-\beta_1^{t+1}},\quad
\hat{\mathbf{v}} = \frac{\mathbf{v}_{t+1}}{1-\beta_2^{t+1}} \\
\theta_{t+1} &= \theta_t - \eta \frac{\hat{\mathbf{m}}}{\sqrt{\hat{\mathbf{v}}}+\varepsilon}
\end{aligned}
$$

여기서 $\mathbf{g}_t=\nabla_\theta L_{\mathcal{B}}(\theta_t)$입니다.

학습률 스케줄 예 (코사인, $t=0\ldots T$):

$$
\eta_t = \eta_{\min} + \tfrac{1}{2}(\eta_{\max}-\eta_{\min})\bigl(1+\cos(\pi t/T)\bigr)
$$

> 💡 **팁**
>
> LLM pretraining은 AdamW(가중치 감쇠가 분리된 Adam) + 코사인/워밍업 조합이 흔합니다. 원리는 위 식과 같습니다.

## LLM에서는 어디에 사용될까?
인과 언어 모델의 한 스텝은 개념적으로 동일하다.

```python
optimizer.zero_grad(set_to_none=True)
logits = model(input_ids)                 # (batch, seq, vocab)
loss = F.cross_entropy(
    logits[:, :-1].reshape(-1, vocab),
    input_ids[:, 1:].reshape(-1),
)
loss.backward()
torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm)
optimizer.step()
scheduler.step()
```

추가되는 것들:

- **Gradient clipping** — 기울기 폭주 방지
- **LR scheduler** — warmup + cosine decay 등
- **AdamW** — 가중치 감쇠와 적응 학습률 결합
- **mixed precision** — 메모리·속도
- **accumulation** — 큰 배치를 흉내

하지만 제거해도 남는 뼈대는 여전히 다섯 단계다. 3권 Training Loop·Optimizer 강의는 이번 강의를 전제로 한다.

## 실습
### 실습 1 — zero_grad 제거 실험

**목표:** Gradient 누적을 눈으로 확인한다.

1. 정상 루프의 epoch 1 Loss를 기록한다.
2. `optimizer.zero_grad()`를 주석 처리하고 다시 실행한다.
3. Loss 변화나 `nan` 여부를 비교한다.

### 실습 2 — 학습률 스윕

**목표:** $\eta$의 효과를 체감한다.

Adam으로 `lr ∈ {1e-4, 1e-3, 1e-2, 1e-1, 1.0}`를 20 epoch 학습하고 최종 Loss를 표로 정리한다.

### 실습 3 — 분류 루프로 확장

**목표:** MSE 대신 Cross Entropy를 쓴다.

1. 2차원 입력, 3클래스 라벨의 장난감 데이터를 만든다.
2. `nn.CrossEntropyLoss`로 학습한다.
3. `model.eval()` + `torch.no_grad()`로 정확도를 계산한다.

**추가 도전:** 같은 설정에서 SGD와 Adam의 정확도 곡선을 비교한다.

## 자주 하는 실수
1. **`zero_grad`를 루프 밖에 한 번만 호출한다**  
   매 배치마다 호출해야 한다. (Accumulation을 의도한 경우는 예외)

2. **`loss.backward()` 없이 `step()`만 한다**  
   `.grad`가 없어 갱신이 없거나 오류가 난다.

3. **`loss`가 텐서인데 `.item()` 없이 누적 출력한다**  
   그래프가 커져 메모리 누수로 이어질 수 있다. 로그는 스칼라로.

4. **평가 때도 `train()` 모드로 둔다**  
   Dropout 등이 켜져 메트릭이 흔들린다.

5. **학습률을 바꾸지 않고 Optimizer만 탓한다**  
   같은 Adam도 $\eta$에 따라 성공/실패가 갈린다.

## 핵심 요약
- 표준 학습 스텝은 `zero_grad → forward → loss → backward → step`이다.
- Optimizer는 `.grad`를 사용해 파라미터를 갱신한다.
- SGD는 고정 보폭, Adam은 적응 보폭에 가깝다.
- 학습률은 가장 먼저 의할 하이퍼파라미터다.
- LLM 학습도 같은 뼈대 위에 clipping·scheduler·분산 학습이 쌓인다.

## 용어 사전
| 용어 | 의미 |
|---|---|
| Training Loop | 배치를 순회하며 파라미터를 갱신하는 반복 절차 |
| Optimizer | Gradient로 파라미터를 업데이트하는 객체 |
| SGD | 배치 Gradient로 하강하는 기본 최적화 방법 |
| Adam | 모멘트 기반으로 보폭을 적응시키는 최적화기 |
| AdamW | 가중치 감쇠 방식이 분리된 Adam 변형 |
| Learning Rate | 한 스텝 업데이트 크기 비율 |
| `zero_grad` | 파라미터 `.grad`를 초기화 |
| `step` | Optimizer 규칙에 따라 파라미터 갱신 |
| Gradient Accumulation | 여러 번 backward 후 한 번 step 하는 기법 |

```python
    pred = model(xb)
    loss = criterion(pred, yb)
    optimizer.step()
    loss.backward()
```

### 문제 5 (연결)

LLM 학습 로그에 `loss`와 `lr`이 같이 찍히는 이유를 학습 루프 관점에서 설명하시오.

---

## 정답 및 해설
### 문제 1

`zero_grad`(기울기 초기화) → forward(예측) → loss(손실 계산) → backward(기울기 계산) → step(파라미터 갱신).

### 문제 2

`backward`는 기본적으로 `.grad`에 더한다. 이전 배치 기울기를 지우지 않으면 갱신 방향이 여러 배치의 합이 되어 버린다.

### 문제 3

$$

1.0 - 0.05 \times 2.0 = 0.9

$$

### 문제 4

(1) `zero_grad` 없음 (2) `step`이 `backward`보다 앞섬 (3) 따라서 올바른 순서로 재배치 필요: `zero_grad → forward → loss → backward → step`.

### 문제 5

Loss는 현재 배치의 학습 신호 크기이고, lr은 step에서 실제 이동량에 곱해지는 스케일이다. 둘을 함께 봐야 “손실이 안 떨어지는 원인”이 모델인지 보폭인지 분리하기 쉽다. Scheduler를 쓰면 lr이 시간에 따라 변하므로 더더욱 로그에 남긴다.
