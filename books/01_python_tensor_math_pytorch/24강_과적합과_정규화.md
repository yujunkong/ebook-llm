# 24강. 과적합과 정규화
## 이번 강에서 배우는 내용

- 과적합(overfitting)과 과소적합(underfitting)을 구분한다.
- train/validation 분리가 왜 필요한지 설명한다.
- Dropout, weight decay, early stopping의 역할과 사용 시점을 안다.
- LLM에서 “암기”와 “일반화”가 어떤 형태로 나타나는지 직관을 연결한다.

## 왜 중요한가?
모델의 목적은 학습 세트를 외우는 것이 아니라, **새로운 입력에도 쓸모 있는 예측**을 하는 것이다. 이 성질을 **일반화(generalization)**라고 한다.

학습 Loss만 보고 모델을 고르면 다음이 자주 일어난다.

- 훈련 정확도는 99%
- 검증 정확도는 60%
- 실제 사용자 입력에서는 더 나쁘다

LLM에서도 같은 현상이 있다. 훈련 말뭉치에 있던 문장을 그대로 뱉거나, 벤치마크 문항에 과하게 맞추고 실제 대화에서는 실패하는 식이다. 규모가 커져도 “검증 신호를 따로 본다”는 원칙은 사라지지 않는다.

## 선수 개념
1. **학습 루프** — train 모드에서 Loss를 낮추는 과정 (제23강)
2. **용량(capacity)** — 모델이 표현할 수 있는 함수의 복잡도 (층 수·너비·파라미터 수)
3. **하이퍼파라미터** — 학습률, 정규화 강도처럼 사람이 정하는 값
4. **평가 모드** — `model.eval()`, `torch.no_grad()` (제23강)

## 핵심 개념
### 3.1 과적합과 과소적합

**과적합(Overfitting)**은 모델이 훈련 데이터의 세부·잡음까지 맞춰, 새 데이터에서 성능이 떨어지는 현상이다.

**과소적합(Underfitting)**은 모델이 훈련 데이터조차 충분히 설명하지 못하는 현상이다.

| 상태 | Train 성능 | Val 성능 | 흔한 원인 |
|---|---|---|---|
| 과소적합 | 낮음 | 낮음 | 모델이 너무 작음, 학습 부족, 특징 부족 |
| 적절 | 높음 | 높음 | 용량·데이터·정규화가 균형 |
| 과적합 | 매우 높음 | 낮음/하락 | 용량 과다, 데이터 부족, 정규화 부족 |

직관:

```text
과소적합: 너무 단순한 곡선
적절:     진짜 패턴을 따르는 곡선
과적합:   점마다 흔들리며 지나가는 곡선
```

### 3.2 Train / Validation / Test 분리

데이터를 용도별로 나눈다.

| 분할 | 역할 |
|---|---|
| **Train** | 파라미터 갱신에 사용 |
| **Validation (Val)** | 하이퍼파라미터 선택, 조기 종료, 과적합 감시 |
| **Test** | 최종 보고용. 모델을 고르는 데 반복 사용하지 않음 |

핵심 규칙:

- Val을 보고 Dropout 비율·학습률·에폭을 고를 수 있다.
- Test는 “마지막에 한 번”에 가깝게 아낀다.
- Train Loss만으로 모델을 선택하지 않는다.

작은 실습에서는 Test를 생략하고 Train/Val만 쓰기도 한다. 그래도 Val은 가능한 한 둔다.

### 3.3 Dropout

**Dropout(드롭아웃)**은 학습 중 일부 유닛을 확률적으로 0으로 만들어, 특정 뉴런 조합에 대한 의존을 줄이는 정규화 기법이다.

```python
self.dropout = nn.Dropout(p=0.5)

def forward(self, x):
    x = self.fc1(x)
    x = self.act(x)
    x = self.dropout(x)  # 학습 시에만 무작위 마스크
    x = self.fc2(x)
    return x
```

- `model.train()`: 드롭 활성화
- `model.eval()`: 드롭 비활성화 (전체 유닛 사용, 스케일 보정)

Dropout은 “여러 부분망의 앙상블을 근사한다”는 직관으로 자주 설명된다. LLM/Transformer에서는 고전 MLP Dropout과 함께, attention dropout·residual dropout 형태도 사용된다.

### 3.4 Weight Decay

**Weight Decay(가중치 감쇠)**는 파라미터의 크기가 커지는 것을 억제하는 정규화다. 흔히 Loss에 가중치 제곱항을 더하는 효과와 연결된다.

$$

L_{\text{total}} = L_{\text{data}} + \frac{\lambda}{2}\|\theta\|^2

$$

SGD에서는 `weight_decay` 인자로 넣는다.

```python
torch.optim.SGD(model.parameters(), lr=0.01, weight_decay=1e-4)
```

Adam 계열에서는 **AdamW**가 가중치 감쇠를 더 명시적으로 분리해 적용한다. LLM 학습 설정에 `weight_decay=0.1` 같은 값이 자주 등장하는 이유다.

직관: “설명력이 비슷한 해 중 파라미터 크기가 작은 쪽을 선호”.

### 3.5 Early Stopping

**Early Stopping(조기 종료)**은 검증 성능이 더 이상 나아지지 않으면 학습을 멈추는 기법이다.

전형적인 절차:

1. 매 epoch 끝에서 val metric을 측정한다.
2. 최고 기록이면 체크포인트를 저장한다.
3. 개선이 없는 epoch가 `patience`회 연속이면 중단한다.
4. 최종 모델은 “마지막”이 아니라 “최고 val” 체크포인트로 복원한다.

과적합이 시작된 뒤에도 Train Loss는 계속 내려갈 수 있다. Early stopping은 그 유혹을 끊는 장치다.

### 3.6 그 밖의 정규화 감각

이름을만 알아 두자. 상세는 이후 강의에서 확장한다.

- **데이터 증강** — 입력을 변형해 사실상 데이터 수를 늘린다.
- **Label smoothing** — 정답 분포를 부드럽게.
- **LayerNorm / BatchNorm** — 활성 분포를 안정화 (정규화의 다른 축).
- **Gradient clipping** — 폭주 방지 (엄밀히는 최적화 안정화).

## 직관적으로 이해하기
시험 공부로 비유한다.

- **과소적합**: 교과서 요약조차 못 외운 상태. 연습문제·실전 모두 못 푼다.
- **과적합**: 작년 기출 답안을 통째로 암기. 연습 점수는 높은데 숫자만 바뀐 새 문제에 무너진다.
- **정규화**: 암기 대신 원리로 풀도록 강제하는 공부법.
- **Validation**: 아직 안 본 모의고사.
- **Test**: 실제 본고사. 모의고사로 전략을 다 정한 뒤 마지막에 본다.

Dropout은 “공부할 때마다 무작위로 참고서를 가리고 풀게 하기”.  
Weight decay는 “너무 복잡한 암기 노트를 쓰지 않게 분량 제한”.  
Early stopping은 “모의고사 점수가 떨어지기 시작하면 그만 벼락치기”.

## 수학적으로 이해하기
가설 집합 $\mathcal{H}$에서 경험 위험(훈련 손실)

$$

\hat{R}(\theta) = \frac{1}{N}\sum_{i=1}^{N}\ell(f_\theta(x_i), y_i)

$$

를 최소화해도, 진짜 위험

$$

R(\theta) = \mathbb{E}_{(x,y)}\big[\ell(f_\theta(x), y)\big]

$$

이 작다는 보장은 없다. 데이터가 적고 $\mathcal{H}$가 크면 $\hat{R}$과 $R$의 간극이 커질 수 있다.

정규화는 목적함수나 탐색 경로를 바꿔, 복잡하고 불안정한 해보다 **단순·안정적인 해**를 선호하게 만든다. Validation은 $R$의 **표본 추정**을 훈련과 분리된 데이터로 수행하는 실천적 방법이다.

## 작은 숫자로 직접 계산하기
훈련 점 4개에 1차 직선으로도 대략 맞출 수 있는 데이터가 있다고 하자. 그런데 3차 다항식으로 맞추면 훈련 오차는 0에 가까워질 수 있다.

```text
x:  0   1   2   3
y:  0   1   1.9 3.1   (거의 직선 + 작은 잡음)
```

직선 $y=x$의 훈련 MSE는 작다.  
고차 다항식이 점마다 정확히 지나가면 훈련 MSE는 더 작아질 수 있지만, $x=1.5$에서의 예측은 크게 흔들릴 수 있다.

신경망에서도 같다. 파라미터를 늘리면 훈련 Loss를 거의 0으로 만들 여력이 생기지만, Val이 먼저 나빠지는 지점이 온다.

## 코드로 구현하기 — 과적합을 만드는 장난감
의도적으로 **데이터는 적고 모델은 큰** 상황을 만든다.

```python
# overfit_demo.py
import torch
import torch.nn as nn
from torch.utils.data import TensorDataset, DataLoader, random_split

def make_spiral_like(n=40, seed=0):
    """2D 입력, 2클래스. 샘플 수를 작게 유지해 과적합을 유도한다."""
    g = torch.Generator().manual_seed(seed)
    x = torch.randn(n, 2, generator=g)
    # 비선형 결정: x0^2 + x1 > 0
    y = (x[:, 0] ** 2 + x[:, 1] > 0).long()
    return x, y

class FatMLP(nn.Module):
    def __init__(self, dropout_p=0.0):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(2, 128),
            nn.ReLU(),
            nn.Dropout(dropout_p),
            nn.Linear(128, 128),
            nn.ReLU(),
            nn.Dropout(dropout_p),
            nn.Linear(128, 2),
        )

    def forward(self, x):
        return self.net(x)

@torch.no_grad()
def accuracy(model, loader):
    model.eval()
    correct = 0
    total = 0
    for xb, yb in loader:
        pred = model(xb).argmax(dim=1)
        correct += (pred == yb).sum().item()
        total += yb.numel()
    return correct / total

def run(dropout_p=0.0, weight_decay=0.0, epochs=80):
    torch.manual_seed(0)
    x, y = make_spiral_like(n=60)
    ds = TensorDataset(x, y)
    train_ds, val_ds = random_split(ds, [40, 20], generator=torch.Generator().manual_seed(0))
    train_loader = DataLoader(train_ds, batch_size=16, shuffle=True)
    val_loader = DataLoader(val_ds, batch_size=32)

    model = FatMLP(dropout_p=dropout_p)
    opt = torch.optim.AdamW(model.parameters(), lr=1e-3, weight_decay=weight_decay)
    crit = nn.CrossEntropyLoss()

    best_val = -1.0
    best_state = None
    patience, wait = 15, 0

    for epoch in range(1, epochs + 1):
        model.train()
        for xb, yb in train_loader:
            opt.zero_grad()
            loss = crit(model(xb), yb)
            loss.backward()
            opt.step()

        tr = accuracy(model, train_loader)
        va = accuracy(model, val_loader)
        print(f"epoch {epoch:03d} | train_acc={tr:.3f} val_acc={va:.3f}")

        if va > best_val:
            best_val = va
            best_state = {k: v.detach().cpu().clone() for k, v in model.state_dict().items()}
            wait = 0
        else:
            wait += 1
            if wait >= patience:
                print(f"early stop at epoch {epoch}")
                break

    model.load_state_dict(best_state)
    print("best val_acc:", best_val)
    return model
```

실험 제안:

1. `dropout_p=0, weight_decay=0` — train 상승, val 정체/하락 관찰
2. `dropout_p=0.5` — 간격이 줄어드는지 비교
3. `weight_decay=1e-2` — 과적합 완화 여부 비교
4. early stopping이 저장한 체크포인트와 마지막 에폭 성능 비교

## 수식 보강 — 과적합과 정규화

경험 위험과 정규화:

$$
\min_\theta\ \hat{L}(\theta) + \lambda\,\Omega(\theta)
$$

$L2$ 가중치 감쇠는 $\Omega(\theta)=\frac{1}{2}\|\theta\|_2^2$입니다. Dropout은 학습 시 활성의 일부를 확률 $p$로 0으로 만들어 앙상블 효과를 냅니다. Early stopping은 검증 손실이 나빠지기 전에 $\theta$를 고정하는 절차입니다.

## 과적합 · 정규화 수식

경험 위험과 일반화:

$$
L_{\mathrm{emp}}(\theta)=\frac{1}{N}\sum_i\ell_i,\qquad
L_{\mathrm{gen}}=\mathbb{E}_{\mathrm{new}}[\ell]
$$

Weight decay:

$$
L_{\mathrm{reg}}=L_{\mathrm{emp}}+\frac{\lambda}{2}\|\theta\|_2^2
$$

Dropout (훈련 시):

$$
\tilde{h}= \frac{m\odot h}{1-p},\quad m_j\sim\mathrm{Bernoulli}(1-p)
$$

```python
import torch.nn as nn
net = nn.Sequential(
    nn.Linear(32, 64),
    nn.ReLU(),
    nn.Dropout(0.1),  # 과적합 완화
    nn.Linear(64, 4),
)
print(sum(p.numel() for p in net.parameters()))
```

## LLM에서는 어디에 사용될까?
LLM의 과적합은 표 형태 분류와 조금 다른 얼굴로 나타난다.

1. **암기(memorization)**  
   훈련 말뭉치의 문장·코드를 그대로 재현. 유용할 때도 있으나 개인정보·저작권 위험을 만든다.

2. **벤치마크 과적합**  
   공개 평가 세트가 훈련/필터링에 섞이면 점수는 높은데 실제 사용자 분포에서 약하다.

3. **SFT 과적합**  
   지시 데이터 스타일만 과하게 맞춰, 일반 언어 능력이 깎이거나 특정 템플릿에만 잘 반응한다.

대응의 큰 줄기는 같다.

- held-out validation / 별도 eval suite
- weight decay, dropout (모델에 따라 비중 다름)
- early stopping / 중간 체크포인트 선택
- 데이터 다양성·중복 제거 (사실상 가장 강력한 “정규화”)
- 이후 권의 Preference/RL 단계는 “정답 암기”가 아닌 **선호·검증 가능한 보상**으로 행동을 조절

1권에서 배울 핵심은 기법이 아니라 **Train 점수와 Val 점수를 분리해 보는 습관**이다.

### 실습 3 — Early Stopping 구현 확인

**목표:** “마지막 모델 ≠ 최고 모델”을 확인한다.

1. patience를 작게(예: 5) 둔다.
2. 중단 시점의 val과, 복원된 best checkpoint의 val을 비교한다.
3. 왜 최종 평가에 best를 쓰는지 문장으로 적는다.

**추가 도전:** 모델 너비를 32로 줄여 과소적합을 만들고, 정규화를 켜면 오히려 해가 되는지 관찰한다.

## 자주 하는 실수
1. **Test 세트로 하이퍼파라미터를 반복 튜닝한다**  
   Test가 사실상 Val이 되어 최종 숫자가 낙관적으로 왜곡된다.

2. **Dropout을 켠 채 평가한다 (`train()` 모드)**  
   메트릭이 무작위적으로 흔들린다. 평가는 `eval()`.

3. **Train Loss만 보고 “학습 성공”이라고 판단한다**  
   과적합의 고전적 함정이다.

4. **데이터가 이미 적은데 강한 Dropout을 켠다**  
   과소적합으로 기울 수 있다. Val을 보고 조절한다.

5. **Early stopping을 하면서 최고 체크포인트를 저장하지 않는다**  
   멈춘 순간의 모델이 최고가 아닐 수 있다.

## 수식 보강 — 일반화 갭과 정규화

### 일반화 갭

훈련 위험(또는 에러)을 $R_{\mathrm{train}}$, 검증을 $R_{\mathrm{val}}$이라 하면 **일반화 갭**은

$$
\Delta = R_{\mathrm{val}} - R_{\mathrm{train}}
$$

로 볼 수 있습니다. 과적합이 진행되면 보통 $R_{\mathrm{train}}$은 계속 줄고 $\Delta$는 커집니다. (정확한 정의는 설정·메트릭에 따라 달라지며, 여기서는 감시용 직관입니다.)

### Weight decay 항

데이터 Loss에 $L_2$ 페널티를 더하면

$$
L_{\mathrm{total}}(\theta) = L_{\mathrm{data}}(\theta) + \frac{\lambda}{2}\|\theta\|_2^2
$$

입니다. $\lambda$가 커질수록 파라미터가 커지는 해보다 **작은 노름**의 해를 선호합니다.

### Early stopping을 지시식으로

검증 점수가 $t$ 스텝에서 최고인지 여부는

$$
\mathrm{improve}(t) = \big[R_{\mathrm{val}}(t) < \min_{s<t} R_{\mathrm{val}}(s)\big]
$$

처럼 쓸 수 있습니다. `patience`회 연속 improve가 없으면 중단합니다.

### 미니 예제 — 숫자로 보는 train/val

어떤 에폭에서 train acc $=0.98$, val acc $=0.70$이면 갭이 큽니다.

$$
\Delta_{\mathrm{acc}} = 0.98 - 0.70 = 0.28
$$

같은 설정에서 dropout·weight decay를 켠 뒤 val이 $0.82$로 오르면, 훈련 점수가 조금 낮아져도 **검증이 나아진 쪽**을 선택하는 것이 일반화 관점입니다.

### 용량과 데이터 크기의 균형

모델 용량(대략 파라미터 수 $|\theta|$)이 데이터 규모에 비해 과도하면 암기가 쉬워집니다. 정성적으로

$$
\text{과적합 위험} \uparrow \quad\text{when}\quad |\theta| \gg \text{효과적 샘플 수}
$$

로 기억하면 됩니다. 해결은 항상 “모델만 키우기”가 아니라 **데이터·정규화·조기 종료**의 조합입니다.

### Dropout 확률 $p$

학습 시 각 유닛을 확률 $p$로 끄는 것은, 기댓값 관점에서 출력을 $(1-p)$배 스케일하는 효과와 연결됩니다. eval에서는 마스크 없이 전체 유닛을 쓰고 스케일을 보정합니다. 초보 단계에서는

$$
\text{train: 무작위 마스크},\qquad \text{eval: 마스크 없음}
$$

만 확실히 구분하면 충분합니다. `model.train()` / `model.eval()` 전환을 잊으면 검증 수치가 왜곡됩니다.

### LLM에서의 형태

대규모 언어 모델도 validation perplexity·held-out loss로 과적합을 감시합니다. 문장을 통째로 외운 듯한 출력, 벤치마크에만 강한 현상은 24강의 $\Delta$ 갭과 같은 가족입니다.

## 핵심 요약
- 과적합은 훈련에는 잘 맞고 새 데이터에는 약한 상태다.
- Train/Val/Test를 분리해, 모델 선택은 Val 기준으로 한다.
- Dropout은 학습 중 유닛을 무작위 차단하고, 평가 때는 끈다.
- Weight decay는 파라미터 크기를 억제하는 정규화다.
- Early stopping은 Val이 나빠지기 전에 최고 체크포인트를 고른다.
- LLM에서도 암기·벤치마크 과적합을 Val/Eval로 감시하는 같은 원칙이 적용된다.

## 용어 사전
| 용어 | 의미 |
|---|---|
| Overfitting | 훈련 데이터에 과도 적합해 일반화가 나빠지는 현상 |
| Underfitting | 훈련 데이터조차 충분히 설명하지 못하는 현상 |
| Generalization | 본 적 없는 데이터에서의 성능 |
| Validation Set | 모델·하이퍼파라미터 선택용 held-out 데이터 |
| Dropout | 학습 중 유닛을 확률적으로 끄는 정규화 |
| Weight Decay | 가중치 크기 억제 정규화 |
| AdamW | 가중치 감쇠를 분리 적용하는 Adam 변형 |
| Early Stopping | Val 개선이 멈출 때 학습을 중단하는 기법 |
| Memorization | 모델이 훈련 사례를 사실상 저장·재현하는 현상 |

### 문제 1

학습 때는 무작위 마스킹으로 정규화 효과를 내고, 평가 때는 결정 출력을 안정적으로 쓰기 위해 드롭을 비활성화(및 스케일 보정)한다.
