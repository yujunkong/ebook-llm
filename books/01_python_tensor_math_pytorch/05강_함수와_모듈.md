# 5강. 함수와 모듈
## 이번 강에서 배우는 내용

- def로 함수를 정의하고 return으로 결과를 돌려준다
- 위치 인자, 기본값 인자, \*args, \*\*kwargs를 사용한다
- import로 모듈·패키지를 불러온다
- `if __name__ == "__main__"`의 역할을 설명한다
- 작은 학습 유틸 함수를 모듈로 분리한다

## 왜 중요한가?
LLM 코드는 한 파일에 모든 것을 넣지 않는다.

```text
tokenize()
embed()
attention()
transformer_block()
loss_fn()
train_step()
generate()
```

각 단계는 함수(또는 클래스 메서드)로 묶인다.  
함수를 모르면 “전체를 복사해 조금씩 고치는” 방식으로만 코드를 다루게 되고, 버그 추적이 급격히 어려워진다.

모듈은 그 다음 단계이다. 관련 함수를 파일로 나누면, Tokenizer·Model·Trainer를 독립적으로 테스트할 수 있다.

## 선수 개념
### 2.1 Function (함수)

**Function(함수)**는 입력(인자)을 받아 작업을 수행하고, 필요할 때 출력(반환값)을 주는 코드 블록이다.

왜 필요한가?

1. 같은 코드를 여러 번 복붙하지 않는다
2. 이름이 의도를 설명한다
3. 단위 테스트와 교체가 쉬워진다

### 2.2 Module (모듈)

**Module(모듈)**은 재사용할 코드가 들어 있는 `.py` 파일이다.  
**Package(패키지)**는 모듈을 모아 둔 폴더(보통 `__init__.py` 포함)이다.

```text
project/
  utils.py          ← 모듈
  model.py          ← 모듈
  train.py          ← 실행 스크립트
```

## 핵심 개념
### 3.1 함수 정의와 호출

```python
def add(a: int, b: int) -> int:
    """두 정수를 더해 반환한다."""
    return a + b

result = add(2, 3)
print(result)  # 5
```

구성 요소:

- `def`: 함수 정의 키워드
- `add`: 함수 이름
- `a`, `b`: **Parameter(매개변수)** — 정의 쪽 이름
- `2`, `3`: **Argument(인자)** — 호출 때 넘기는 값
- `return`: 호출한 곳으로 값을 돌려줌

수학에서 함수 $f$가

$$
f:\mathbb{R}\times\mathbb{R}\to\mathbb{R},\qquad f(a,b)=a+b
$$

이듯이, 파이썬 함수도 **입력 공간 → 출력 공간**의 대응입니다. `add(2,3)`은 $f(2,3)=5$를 계산하는 호출입니다.

`return`이 없으면 함수는 `None`을 반환한다.

```python
def log_hi() -> None:
    print("hi")

x = log_hi()
print(x)  # None
```

### 3.2 기본값 인자

자주 쓰는 값에는 기본값을 둔다.

```python
def greet(name: str, prefix: str = "Hello") -> str:
    return f"{prefix}, {name}"

print(greet("LLM"))                 # Hello, LLM
print(greet("LLM", prefix="안녕"))  # 안녕, LLM
```

주의: 기본값에 가변 객체(`list`, `dict`)를 바로 넣지 않는 편이 안전하다. 의도치 않게 상태가 공유될 수 있다.

```python
# 비권장
def add_token(token: str, bag: list[str] = []) -> list[str]:
    bag.append(token)
    return bag
```

권장 패턴:

```python
def add_token(token: str, bag: list[str] | None = None) -> list[str]:
    if bag is None:
        bag = []
    bag.append(token)
    return bag
```

### 3.3 키워드 인자

인자를 이름과 함께 넘기면 가독성이 좋아진다.

```python
def train_step(loss: float, lr: float, weight_decay: float = 0.0) -> float:
    # 아주 단순한 가짜 업데이트 규칙
    return loss * (1.0 - lr) + weight_decay

print(train_step(loss=2.0, lr=0.1, weight_decay=0.01))
```

위치가 바뀌어도 이름이 있으면 안전하다.

### 3.4 *args와 **kwargs

**\*args**는 임의 개수의 위치 인자를 튜플로 받는다.  
**\*\*kwargs**는 임의 개수의 키워드 인자를 딕셔너리로 받는다.

```python
def summarize(*values: float, **options: str) -> str:
    total = sum(values)
    name = options.get("name", "sum")
    return f"{name}={total}"

print(summarize(1.0, 2.0, 3.0, name="loss_sum"))
```

출력:

```text
loss_sum=6.0
```

라이브러리 API를 감쌀 때 자주 등장한다. 다만 남용하면 타입이 흐려지므로, 공개 함수에서는 필요한 인자를 명시하는 편이 좋다.

### 3.5 스코프 (Scope)

함수 안에서 만든 변수는 기본적으로 함수 밖과 분리된다.

```python
x = 10

def f() -> None:
    x = 20  # 함수 내부의 새 이름
    print("in f:", x)

f()
print("outside:", x)
```

출력:

```text
in f: 20
outside: 10
```

전역 변수를 함수에서 직접 바꾸려면 `global`이 필요하지만, 학습 코드에서는 **인자와 반환값으로 데이터를 주고**하는 쪽이 훨씬 안전하다.

### 3.5.1 합성 함수 — LLM 파이프라인의 원형

수학의 합성

$$
(h\circ g\circ f)(x) = h(g(f(x)))
$$

는 코드에서 함수를 잇는 것과 같습니다.

```python
def tokenize(text: str) -> list[str]:
    return text.split()

def length(tokens: list[str]) -> int:
    return len(tokens)

def describe(text: str) -> str:
    return f"n_tokens={length(tokenize(text))}"
```

`describe`는 $h\circ g\circ f$의 축소판입니다. 나중에 `tokenize → embed → transform → project`도 같은 합성 구조입니다.

### 3.6 import

다른 파일의 함수를 가져온다.

```python
# math_utils.py
def square(x: float) -> float:
    return x * x
```

```python
# main.py
import math_utils

print(math_utils.square(4))
```

다른 형태:

```python
from math_utils import square
print(square(4))

import math_utils as mu
print(mu.square(4))
```

표준 라이브러리도 같은 방식으로 쓴다.

```python
import math
print(math.log(2.718281828))
```

### 3.7 if __name__ == "__main__"

이 패턴은 “파일이 **직접 실행될 때만**” 아래 코드를 돌리겠다는 뜻이다.

```python
# toy_module.py

def normalize_score(x: float) -> float:
    return x / 10.0

def _demo() -> None:
    print(normalize_score(25.0))

if __name__ == "__main__":
    _demo()
```

- `python toy_module.py`로 실행 → `__name__`이 `"__main__"` → `_demo()` 실행
- 다른 파일이 `import toy_module` → `__name__`이 `"toy_module"` → `_demo()`는 실행되지 않음

모듈을 import만 했는데 데모 출력이나 학습이 시작되는 사고를 막는다.

## 직관적으로 이해하기
함수는 공장의 **공정 박스**이다.

```text
입력(재료) → 함수(공정) → 출력(반제품)
```

모듈은 그 박스들을 모아 둔 **작업실 선반**이다.

LLM 학습을 공장으로 보면:

| 함수 | 공정 |
|---|---|
| `tokenize` | 텍스트를 ID로 |
| `forward` | ID를 logits로 |
| `compute_loss` | logits와 정답으로 loss |
| `optimizer_step` | 파라미터 갱신 |
| `save_checkpoint` | 상태 저장 |

좋은 학습 코드는 “한 거대한 스크립트”보다 **이름이 있는 공정들의 조립**에 가깝다.

## 작은 숫자 예제 — Cross-Entropy 전 단계의 오차
아직 Softmax/Cross-Entropy는 배우지 않았다.  
다만 “예측 점수와 정답 인덱스의 차이”를 함수로 감싸 보자.

정답 토큰 인덱스: `1`  
예측 점수: `[2.0, 5.0, 1.0]`  
정답 위치 점수와 최댓값의 차이를 margin으로 본다.

```python
# margin_utils.py
# 목적: 함수로 "정답 점수가 얼마나 강한지"를 계산한다.

def score_margin(scores: list[float], target_index: int) -> float:
    target_score = scores[target_index]
    best_score = max(scores)
    return target_score - best_score

if __name__ == "__main__":
    scores = [2.0, 5.0, 1.0]
    print(score_margin(scores, target_index=1))  # 0.0 (이미 최대)
    print(score_margin(scores, target_index=0))  # -3.0
```

해석:

- margin이 0이면 정답이 최고 점수
- 음수면 다른 토큰이 더 높음 → “틀리는 쪽”

나중에 이 자리가 실제 loss 함수로 교체된다.

수식으로 다시 쓰면, 점수 벡터 $\mathbf{s}=(s_0,\ldots,s_{V-1})$와 정답 인덱스 $y$에 대해

$$
m(\mathbf{s}, y) = s_y - \max_j s_j
$$

입니다. $m=0$이면 정답이 최댓값, $m<0$이면 다른 토큰이 더 큽니다.

### 미니 예제 — 평균을 함수 $f$로

배치 loss 목록 $\mathbf{L}=(L_1,\ldots,L_n)$의 평균은

$$
f(\mathbf{L}) = \frac{1}{n}\sum_{i=1}^{n} L_i
$$

입니다.

```python
def mean(values: list[float]) -> float:
    n = len(values)
    if n == 0:
        raise ValueError("empty")
    return sum(values) / n

print(mean([2.0, 4.0, 6.0]))  # 4.0
```

함수로 감싸면 “평균을 어떻게 구하는지”가 한곳에 모이고, 학습 루프는 `mean(batch_losses)`만 호출하면 됩니다.

### 미니 예제 — temperature가 있는 스케일 함수

온도 $\tau>0$으로 로짓을 나눈다는 아이디어는 나중에 Softmax에서 본격화합니다. 지금은 함수 시그니처만 익힙니다.

$$
g(\mathbf{z};\tau) = \frac{\mathbf{z}}{\tau}
$$

```python
def scale_logits(logits: list[float], temperature: float = 1.0) -> list[float]:
    if temperature <= 0:
        raise ValueError("temperature must be positive")
    return [z / temperature for z in logits]

print(scale_logits([2.0, 4.0], temperature=2.0))  # [1.0, 2.0]
```

기본값 $\tau=1$이면 입력을 그대로 두는 항등 스케일입니다. **기본값 인자**가 “보통의 경우”를 표현하는 좋은 예입니다.

## 코드로 모듈 분리하기
```python
# text_ops.py
# 목적: 토큰화 흉내 함수를 모듈로 분리한다.

def tokenize(text: str) -> list[str]:
    """공백 기준의 아주 단순한 토큰화."""
    return text.strip().split()

def detokenize(tokens: list[str]) -> str:
    return " ".join(tokens)
```

```python
# generate_mini.py
# 목적: 모듈을 import해 생성 루프를 조립한다.

from text_ops import tokenize, detokenize

def next_token(tokens: list[str]) -> str:
    last = tokens[-1]
    table = {"딥러닝을": "배운다", "배운다": "끝"}
    return table.get(last, "...")

def generate(prompt: str, steps: int = 3) -> str:
    tokens = tokenize(prompt)
    for _ in range(steps):
        tokens.append(next_token(tokens))
        if tokens[-1] == "끝":
            break
    return detokenize(tokens)

if __name__ == "__main__":
    print(generate("딥러닝을", steps=5))
```

파일 두 개로 나뉘었다는 사실 자체가 중요하다.  
이후 강의에서 `text_ops`는 진짜 Tokenizer로, `next_token`은 모델 `forward`로 성장한다.

## 수식 보강 — 함수 $f$

$$
y=f(x_1,\ldots,x_k)
$$

순수 함수는 동일 입력에 동일 출력을 냅니다. 신경망의 `forward`도 $f_\theta$입니다.

합성:

$$
(g\circ f)(x)=g(f(x))
$$

Chain Rule(14강)의 출발점입니다.

## 함수 = 재사용 가능한 연산 블록

```python
def cross_entropy_np(logits, target_index: int) -> float:
    # log-sum-exp 안정화
    import math
    m = max(logits)
    exps = [math.exp(z - m) for z in logits]
    Z = sum(exps)
    return -(logits[target_index] - m - math.log(Z))

print(cross_entropy_np([2.0, 0.5, 0.1], 0))
```

$$
\mathrm{LSE}(z)=m+\log\sum_i e^{z_i-m},\quad
L=-z_y+\mathrm{LSE}(z)
$$

모듈로 나누면 LLM 코드의 `Attention`, `MLP`, `Block`과 같은 사고방식입니다.

## LLM에서는 어디에 사용될까?
| 개념 | LLM에서의 모습 |
|---|---|
| function | `forward`, `encode`, `decode`, `train_one_epoch` |
| return | logits 텐서, loss 스칼라, 생성된 토큰 리스트 |
| kwargs | `generate(max_new_tokens=..., temperature=...)` |
| module | `model.py`, `data.py`, `train.py`, `infer.py` |
| `__main__` | 학습 엔트리포인트와 라이브러리 코드 분리 |

오픈소스 LLM 저장소를 열어 보면, 거대한 한 파일보다 모듈 트리가 먼저 보인다.  
5강에서 익히는 습관이 그대로 그 구조를 읽는 눈이 된다.

### 순수 함수와 부작용

**순수에 가까운 함수**는 같은 입력에 같은 출력을 주고, 바깥 상태를 바꾸지 않습니다. `mean`, `score_margin`이 그에 가깝습니다.

**부작용(side effect)**이 있는 함수는 파일 쓰기, 전역 변경, GPU 상태 변경 등을 수행합니다. `save_checkpoint`가 대표적입니다.

학습 코드에서는 둘 다 필요합니다. 다만 **계산은 순수하게, 저장·로깅은 경계에서** 나누면 테스트가 쉬워집니다.

복잡도 감각: 길이 $n$ 리스트의 합·평균은 $O(n)$입니다. 함수로 감싼다고 점근 복잡도가 바뀌지는 않지만, **가독성과 재사용**이 바뀝니다.

## 자주 하는 실수
1. **return을 잊고 print만 한다**  
   화면 출력과 반환값은 다르다. 계산 결과는 `return`해야 다음 함수에 연결된다.

2. **함수 이름에 동사를 빠뜨린다**  
   `data`, `model1`보다 `load_data`, `build_model`이 읽기 쉽다.

3. **너무 많은 일을 한 함수에 넣는다**  
   “토큰화 + 학습 + 저장”을 한 함수에 몰면 재사용이 불가능하다. 한 함수 한 책임.

4. **순환 import**  
   A가 B를, B가 A를 가져오면 실패한다. 공통 유틸을 세 번째 모듈로 뺀다.

5. **`from module import *`를 남용한다**  
   이름이 어디서 왔는지 추적하기 어렵다. 명시적 import를 선호한다.

## 핵심 요약
- 함수는 입력을 받아 처리하고 결과를 반환하는 재사용 단위이다
- 기본값·키워드 인자·args/kwargs로 호출 방식을 유연하게 만든다
- 모듈은 함수를 파일 단위로 묶은 것이다
- `if __name__ == "__main__"`은 실행과 import를 분리한다
- LLM 코드는 함수·모듈의 조립으로 읽어야 한다
- 함수 $f(x)$·합성 $h\circ g\circ f$는 파이프라인 사고의 수학적 원형이다
- 합·평균 등 $O(n)$ 계산을 함수로 감싸 재사용한다

## 용어 사전
| 용어 | 의미 |
|---|---|
| Function | 이름 있는 재사용 코드 블록 |
| Parameter / Argument | 정의 쪽 이름 / 호출 때 넘기는 값 |
| return | 함수 결과 반환 |
| *args / **kwargs | 가변 위치·키워드 인자 |
| Scope | 이름이 유효한 범위 |
| Module | `.py` 파일 단위 코드 묶음 |
| import | 모듈을 불러오는 구문 |
| `__name__` | 모듈의 이름. 직접 실행 시 `"__main__"` |
| Composition | $h(g(f(x)))$처럼 함수를 이어 붙이는 것 |
| Pure function | 같은 입력→같은 출력, 바깥 상태를 바꾸지 않는 함수에 가까운 형태 |
| Side effect | 파일 쓰기·전역 변경 등 반환 외 효과 |
