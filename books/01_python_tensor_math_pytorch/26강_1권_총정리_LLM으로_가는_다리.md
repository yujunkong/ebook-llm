# 26강. 1권 총정리 — LLM으로 가는 다리
## 이번 강에서 배우는 내용

- 1권에서 익힌 각 개념이 LLM 학습·추론 파이프라인의 어디에 해당하는지
- 스스로 점검할 수 있는 능력 체크리스트
- 2권 제27강(텍스트가 숫자가 되는 과정)으로 넘어가기 전 준비물
- Tokenizer / Transformer가 왜 “별세계”가 아니라 1권의 연장인지

## 왜 중요한가?
1권은 속도가 빠르다. Python에서 시작해 Autograd·Module·학습 루프·미니 프로젝트까지 왔다. 각 강의를 통과해도, 머리속에서는 조각으로 남을 수 있다.

총정리의 목적은 복습 시험이 아니라 **좌표 재정렬**이다.

```text
조각 지식
  → 하나의 파이프라인
    → 2권에서 토큰과 Attention이 꽂힐 소켓 확인
```

## 1권이 답하려 한 질문
한 문장으로 압축하면 다음과 같다.

> 숫자의 배열(Tensor) 위에서, 미분 가능한 모델의 파라미터를, 데이터 배치로 반복 갱신해, 본 적 없는 입력에도 쓸모 있는 예측을 하게 만들 수 있는가?

LLM은 이 문장에서 “숫자 배열”이 **토큰 임베딩**이 되고, “예측”이 **다음 토큰**이 될 뿐이다.

## 개념 지도 — 1권 → LLM 파이프라인
### 3.1 전체 파이프라인 스케치

앞으로 반복해서 보게 될 큰 그림이다.

```text
텍스트
  → (2권) Tokenizer → token ids
    → Embedding → 벡터 서열
      → Transformer Block × N
        → vocab logit
          → Softmax → 다음 토큰 분포
            → Loss / Generation

학습 시:
DataLoader 배치
  → forward
    → loss
      → backward
        → optimizer.step
```

1권은 이 그림에서 **Tokenizer·Attention 특화 블록을 제외한 엔진실**을 담당했다.

### 3.2 강의별로 꽂히는 위치

| 1권 주제 | 대표 강 | LLM에서의 위치 |
|---|---|---|
| 학습 지도·용어 | 1 | 전체 여정의 좌표 |
| Python·자료구조·파일 | 2~7 | 데이터 처리·스크립트·실험 기반 |
| NumPy 배열 | 8 | Tensor 사고의 원형 |
| Scalar/Vector/Matrix/Tensor | 9 | 모든 표현의 형태 |
| 내적·행렬곱 | 10 | Linear, Attention score의 뼈대 |
| 미분·편미분 | 11 | 학습 가능성의 전제 |
| Gradient Descent | 12 | Optimizer의 심장 |
| Loss | 13 | Cross Entropy로 확장될 목적함수 |
| Chain Rule | 14 | Deep net / Autograd의 원리 |
| NN 구조·Forward | 15~16 | 층 쌓기·순전파 |
| Backprop | 17~18 | 수동 검증·디버깅 근육 |
| PyTorch Tensor | 19 | 실전 연산 컨테이너 |
| Autograd | 20 | 대규모 모델 학습의 필수 장치 |
| `nn.Module` | 21 | GPT/Transformer 클래스의 단위 |
| Dataset / DataLoader | 22 | 토큰 배치 공급 |
| 학습 루프·Optimizer | 23 | Pretraining/SFT 루프의 골격 |
| 과적합·정규화 | 24 | 암기 vs 일반화, dropout/decay/early stop |
| 미니 NN 프로젝트 | 25 | “끝까지 학습” 완주 경험 |

이 표를 외울 필요는 없다. **막힐 때마다 어느 소켓을 다시 볼지** 찾는 용도다.

### 3.3 수학 한 줄로 다시 쓰기

학습의 최소 식은 변하지 않았다.

$$

\theta_{t+1} = \theta_t - \eta \nabla_\theta L_B(\theta_t)

$$

LLM에서는

- $\theta$: Embedding + Attention + FFN + … 의 모든 파라미터  
- $L_B$: 배치 안 토큰들의 평균 Cross Entropy  
- $B$: 토큰(또는 시퀀스) 배치  

1권에서 연습한 MSE/BCE는 “Loss라는 스칼라를 정의하고 줄인다”는 연습이었다.

### 3.4 코드 한 줄로 다시 쓰기

```python
for xb, yb in loader:
    optimizer.zero_grad()
    pred = model(xb)
    loss = criterion(pred, yb)
    loss.backward()
    optimizer.step()
```

2·3권에서도 이 다섯 줄의 뼈대는 같다. 바뀌는 것은 `xb`의 의미(토큰), `model`의 내부(Transformer), `criterion`의 형태(next-token CE)다.

## 직관적으로 이해하기 — “엔진은 켰다”
자동차에 비유하자.

- 1권: 엔진·변속기·연료 주입·계기판을 이해했다.
- 2권: 도로 규칙(토큰)과 조향 장치(Attention)를 장착한다.
- 3권: 장거리 주행 훈련(Pretraining)과 운전 매너 교육(SFT)을 한다.
- 4권: 사람 피드백으로 운전 성향을 정렬한다.
- 5권: 실제 고속도로에서 빠르게 달리게 튜닝한다(vLLM·GPU).

엔진 없이 조향만 공부하면 “동작하는 차”가 되지 않는다. 반대로 엔진만 있으면 도로에 못 오른다. 지금이 그 전환점이다.

## 작은 통합 예제 — “아직 텍스트는 아니지만” 같은 루프
토큰 대신 정수 ID를 바로 써 보는 장난감이다. Embedding·Tokenizer 본론은 2권이지만, **이산 입력이 벡터로 바뀌어 모델에 들어가는 느낌**만 미리 본다.

```python
# bridge_preview.py
import torch
import torch.nn as nn
from torch.utils.data import DataLoader, TensorDataset

class TinyTokenClassifier(nn.Module):
    """가짜 token id → Embedding → MLP → 클래스."""

    def __init__(self, vocab_size=50, d_model=8, n_class=3):
        super().__init__()
        self.emb = nn.Embedding(vocab_size, d_model)
        self.fc = nn.Linear(d_model, n_class)

    def forward(self, token_ids):
        # token_ids: (batch, seq)
        x = self.emb(token_ids)          # (batch, seq, d_model)
        x = x.mean(dim=1)                # 아주 거친 "문장 요약"
        return self.fc(x)

def main():
    torch.manual_seed(0)
    # 가짜 데이터: 길이 5의 토큰 서열
    x = torch.randint(0, 50, (200, 5))
    y = torch.randint(0, 3, (200,))
    loader = DataLoader(TensorDataset(x, y), batch_size=32, shuffle=True)

    model = TinyTokenClassifier()
    opt = torch.optim.Adam(model.parameters(), lr=1e-2)
    crit = nn.CrossEntropyLoss()

    model.train()
    for epoch in range(1, 11):
        total = 0.0
        n = 0
        for xb, yb in loader:
            opt.zero_grad()
            loss = crit(model(xb), yb)
            loss.backward()
            opt.step()
            total += loss.item() * xb.size(0)
            n += xb.size(0)
        print(f"epoch {epoch:02d} | loss={total / n:.4f}")

if __name__ == "__main__":
    main()
```

이 코드의 메시지는 “이미 Embedding을 배웠다”가 아니다.  
**1권 도구만으로도 ‘이산 ID 배치 → 벡터 → Loss → 업데이트’가 연결된다**는 감각이다. 진짜 언어 모델은 평균 풀링 대신 Attention으로 문맥을 모은다.

## 2권 미리보기 — 다리가 닿는 곳
### 7.1 제27강에서 시작할 질문

> 텍스트가 어떻게 숫자가 되는가?

사람은 “고양이”를 읽지만, 모델은 결국 `tensor([152, 88, ...])` 같은 정수를 받는다. 그 변환이 **Tokenizer**다.

1권과의 연결:

- 숫자의 배열을 다룰 준비는 끝났다.
- 이제 그 숫자가 **어떤 규칙으로 택스트에서 오는지**를 정한다.

### 7.2 2권에서 이어질 주요 블록 (이름만)

| 주제 | 하는 일 | 기대 선수 지식(1권) |
|---|---|---|
| Tokenizer / BPE | 텍스트 ↔ 토큰 ID | 파이썬·자료구조 |
| Embedding | ID → 벡터 | Tensor, Module |
| Softmax / CE | 다음 토큰 분포·손실 | Loss, 미분 |
| Attention / QKV | 문맥 가중합 | 행렬곱, softmax 직관 |
| Transformer Block | Attention+FFN+잔차+정규화 | MLP, Module 조립 |
| Causal LM | 왼쪽만 보고 다음 토큰 | 학습 루프 |

지금 단계에서 Attention 수식을 미리 외울 필요는 없다. “행렬곱과 softmax가 문맥 가중치를 만든다” 정도만 예고로 충분하다.

### 7.3  ent하지 말아야 할 착각

1. **1권을 건너뛰고 Transformer 튜토리얼만 따라가면 된다**  
   짧은 기간은 빨라 보여도, shape/NaN/과적합 앞에서 해석력이 끊긴다.

2. **PyTorch API만 알면 LLM을 이해한 것이다**  
   API는 엔진 열쇠다. 연료(데이터)·지도(목적함수)·조향(구조)이 남았다.

3. **25강 프로젝트 정확도가 낮으면 2권에 못 간다**  
   기준은 완벽 점수가 아니라, 버그를 고치며 학습 곡선이 움직인 경험이다.

## 1권에서 2권으로 — 수식 지도

1권의 핵심 연산을 한 줄로 압축하면 다음과 같습니다.

$$
y = xW + b,\quad
L = -\log\mathrm{softmax}(z)_y,\quad
\theta\leftarrow\theta-\eta\nabla L
$$

2권은 이 위에 Tokenizer와 $QK^\top$ Attention을 올립니다.

### 선형 → 확률 → 손실 → 갱신

$$
z = xW + b
$$

$$
\hat{y} = \mathrm{softmax}(z),\qquad
L = -\sum_c y_c \log \hat{y}_c
$$

$$
\theta \leftarrow \theta - \eta \nabla_\theta L
$$

임베딩·Attention·LM Head도 같은 골격 위에 올라갑니다.

### Shape로 다시 보기

배치 $B$, 은닉 $d$, 클래스 $C$일 때

$$
x\in\mathbb{R}^{B\times d},\quad
W\in\mathbb{R}^{d\times C},\quad
z\in\mathbb{R}^{B\times C}
$$

LLM에서는 $C$가 vocab size $V$, $x$가 토큰 위치별 은닉상태가 됩니다. 시퀀스가 있으면

$$
H\in\mathbb{R}^{B\times T\times d}
\;\xrightarrow{W_{\mathrm{lm}}}\;
Z\in\mathbb{R}^{B\times T\times V}
$$

입니다.

### Softmax · Cross-Entropy 한 줄 연결

$$
L_i = -z_{i,y_i} + \log\sum_{j=1}^{C}\exp(z_{i,j})
$$

이 형태가 PyTorch `cross_entropy`가 logits에 직접 적용하는 이유입니다.

### 정규화와 일반화

$$
L_{\mathrm{reg}} = L + \lambda\|\theta\|_2^2
$$

Dropout은 학습 시 뉴런을 확률 $p$로 끄고, 추론 시 기댓을 맞춥니다.

### Attention 예고 (2권)

$$
\mathrm{Attention}(Q,K,V)
=
\mathrm{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}}\right)V
$$

1권의 행렬곱·Softmax·Shape 추적이 그대로 이 식의 읽기 도구가 됩니다.

## 파이프라인 수식 지도 — 1권이 남긴 식

### 순전파의 최소 형태

선형층 하나는

$$
\mathbf{y} = \mathbf{x}W + \mathbf{b}
$$

이고, 여러 층을 쌓으면 합성 $f_L\circ\cdots\circ f_1$이 됩니다. Softmax·CE까지 붙이면 분류/다음 토큰 목표와 연결됩니다.

### 배치 Loss

배치 $B$개의 샘플 Loss $L^{(i)}$에 대해

$$
L_B = \frac{1}{B}\sum_{i=1}^{B} L^{(i)}
$$

가 학습 루프가 최소화하는 스칼라입니다. DataLoader는 $(\mathbf{x}^{(i)}, y^{(i)})$를 묶어 $L_B$를 계산할 재료를 공급합니다.

### 파라미터 갱신

$$
\theta_{t+1} = \theta_t - \eta \, \widehat{\nabla_\theta L_B}
$$

에서 $\widehat{\nabla}$는 미니배치로 추정한 Gradient입니다. Autograd가 이 벡터를 계산하고, Optimizer가 $\eta$와 모멘텀 규칙으로 적용합니다.

### 정규화와의 결합

$$
L_B^{\mathrm{reg}} = L_B + \frac{\lambda}{2}\|\theta\|^2
$$

또는 Dropout 마스크를 train 모드에서만 적용하는 것이 24강의 요지입니다. 26강에서는 “식만” 다시 붙입니다.

### 2권으로 이어지는 자리

토큰 ID 서열 $\mathbf{id}\in\mathbb{Z}^{T}$가 Embedding으로

$$
X = \mathrm{Embed}(\mathbf{id}) \in \mathbb{R}^{T\times d}
$$

가 되면, 이후 Attention은 $X$ 위에서의 가중합입니다. 1권은 $X$와 $L_B$와 $\theta$ 갱신을 다룰 준비가 끝났다는 선언입니다.

### 미니 점검 — 다섯 줄 복원

아래를 보지 않고 빈칸을 채울 수 있는지 확인합니다.

$$
\text{zero\_grad} \rightarrow \text{forward} \rightarrow L \rightarrow \text{backward} \rightarrow \text{step}
$$

코드로는 23·25강에서 반복한 그 루프입니다. 막히면 해당 강으로 돌아갑니다.

### 복잡도·규모 감각 (정성)

파라미터 수 $|\theta|$, 토큰 수 $N_{\mathrm{tok}}$가 커질수록 한 스텝 비용은 대체로 함께 커집니다. 1권 미니 MLP에서는 둘 다 작아 **손으로 추적 가능**했습니다. LLM에서는 같은 식 구조가 거대한 $|\theta|$, $N_{\mathrm{tok}}$ 위에 올라갑니다. 식의 형태는 유지되고 **규모만 바뀐다**는 점이 다리의 핵심입니다.

## 핵심 요약
- 1권의 핵심은 Tensor 위에서 Loss를 줄이도록 파라미터를 갱신하는 능력이다.
- Module · DataLoader · Autograd · Optimizer · 정규화는 LLM 학습 스택의 공통 기초다.
- 25강 프로젝트는 그 기초를 “동작하는 학습”으로 증명한 관문이다.
- 2권은 텍스트→토큰→Embedding→Transformer로 이어지며, 엔진 위에 언어 장치를 얹는다.
- 다음 강의(제27강)는 Tokenizer의 입구, “텍스트가 숫자가 되는 과정”이다.

## 용어 사전
| 용어 | 한 줄 의미 |
|---|---|
| Tensor | 학습 계산의 기본 다차원 배열 |
| Gradient | Loss를 파라미터로 미분한 갱신 신호 |
| Loss | 예측과 목표의 차이를 스칼라로 나타낸 것 |
| Backpropagation | Chain rule로 기울기를 층마다 전달하는 절차 |
| Autograd | 그 절차를 자동으로 수행하는 엔진 |
| `nn.Module` | 파라미터를 등록·조합하는 모델 단위 |
| DataLoader | 미니배치 데이터 공급기 |
| Optimizer | Gradient로 파라미터를 업데이트하는 규칙 객체 |
| Overfitting | 훈련에는 맞고 새 데이터에 약한 상태 |
| Generalization | 본 적 없는 데이터에서의 성능 |
| state_dict | 모델 가중치 스냅샷 |
| Tokenizer (미리보기) | 텍스트를 토큰 ID로 바꾸는 장치 |
| Transformer (미리보기) | Attention 기반 문맥 처리 신경망 구조 |
| Next Token Prediction (미리보기) | 이전 토큰으로 다음 토큰을 예측하는 목표 |
