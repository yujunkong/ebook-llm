# 2권. Tokenizer와 Transformer

## 제35강. Attention이 필요한 이유

### 1. 이번 강의에서 배울 것

34강까지로 “한 위치의 logits → Softmax → Cross Entropy”라는 **학습 신호**는 준비되었다.  
이번 강의부터는 그 logits를 만들기 위해 **문맥을 어떻게 모을 것인가**를 다룬다.

이 강의를 마치면 다음을 말할 수 있어야 한다.

- **Attention(어텐션, 주의 메커니즘)**이 무엇을 하려는지 (한 문장 정의)
- RNN·CNN이 긴 문장·긴 의존에서 겪는 한계
- **Long-range dependency(장거리 의존성)**가 언어에서 왜 흔한지
- Attention이 “모든 위치에 직접 연결”을 제공하는 이유
- 36강 Q/K/V로 넘어가기 전, Attention의 **문제 의식**만 또렷이 말하기

수식·구현은 36~40강에서 천천히 쌓는다. 오늘은 **왜**에 집중한다.

### 2. 왜 이것을 배우는가

LLM의 본체는 “거대한 Softmax 분류기”가 아니다.  
본체는 **문맥을 섞어 각 토큰의 표현을 갱신하는 블록**이고, 그 중심이 Attention이다.

```text
토큰들 → Embedding
       → (Attention + FFN) × L층
       → LM Head → Logits → Softmax/CE
```

Attention을 “마법 모듈”로 외우면, 이후 Multi-Head·Mask·RoPE가 전부 공중에 뜬다.  
먼저 “기존 방식으로는 무엇이 부족한가”를 느껴야 한다.

### 3. 먼저 알아야 할 개념

- Embedding (31강): 토큰 → 벡터
- Next-Token Prediction (32강)
- Softmax / Cross Entropy (33~34강)
- 행렬·벡터의 존재 (1권 9~10강)
- 순차 처리 vs 병렬 처리의 직관

오늘 깊이 들어가지 않는 것:

- Query / Key / Value 수식 (36강)
- Causal Mask (40강)
- Multi-Head (41강)

### 4. 핵심 개념 설명

#### 4.1 Attention이란? (예고 정의)

**Attention(어텐션)**은 시퀀스의 각 위치가, 다른 위치들의 정보를 **가중 평균으로 모아** 자신의 새 표현을 만드는 메커니즘이다.

한 줄로:

> “지금 이 토큰을 처리할 때, 문장의 어디에 얼마나 주목할 것인가?”

가중치는 보통 **유사도(점수) → Softmax**로 만든다. 자세한 계산은 37~38강.

#### 4.2 언어에 필요한 “연결”

언어는 국소적 패턴만으로 끝나지 않는다.

예문:

```text
어제 도서관에서 빌린 그 두꺼운 책은 정말 재미있었다.
```

- “재미있었다”의 주어 느낌은 “책”과 연결된다.
- “책”을 수식하는 “두꺼운”, “빌린”도 멀리 떨어져 있다.
- 대명사 “그”는 앞선 명사를 가리킨다.

모델이 다음 토큰을 예측하려면, **멀리 있는 토큰의 정보**가 현재 위치에 도착해야 한다.

#### 4.3 Long-range dependency (장거리 의존성)

**Long-range dependency(장거리 의존성)**는 서로 멀리 떨어진 토큰(또는 시점) 사이에 의미·문법적 관계가 있는 현상이다.

예:

- 주어와 멀리 떨어진 동사의 수일치
- “만약 … 한다면”처럼 멀리 이어지는 조건
- 코드에서 열린 괄호와 닫힌 괄호
- 대화에서 여러 턴 전의 고유명사

거리 \(d\)가 커져도 정보가 약해지지 않고 전달되는 경로가 필요하다.

### 5. 직관적으로 이해하기 — RNN의 한계

#### 5.1 RNN이 문맥을 전달하는 방식

**RNN(Recurrent Neural Network, 순환 신경망)**은 시간을 따라 숨은 상태 \(\mathbf{h}_t\)를 갱신한다.

$$
\mathbf{h}_t = f(\mathbf{h}_{t-1},\ \mathbf{x}_t)
$$

정보 전달 경로:

```text
x1 → h1 → h2 → h3 → … → hT
```

위치 1의 정보가 위치 \(T\)에 가려면 **\(T-1\)번의 순차 전달**을 겪는다.

#### 5.2 무엇이 문제인가?

1. **장거리 신호가 희석·소실되기 쉽다**  
   매 스텝 변환을 거치며 Gradient와 정보가 약해질 수 있다. (vanishing gradient와 연결)

2. **순차 계산이라 병렬화가 어렵다**  
   \(h_t\)가 \(h_{t-1}\)에 의존하므로, 길이 \(T\)를 GPU에서 한 번에 펼치기 어렵다.

3. **“어디에 주목할지”를 명시적으로 고르기 어렵다**  
   상태는 요약본 하나에 압축된다. 필요할 때 과거 특정 토큰을 직접 꺼내 보기 어렵다.

LSTM/GRU는 게이트로 개선했지만, “모든 과거 위치를 직접 조회”하는 구조는 아니다.

#### 5.3 비유 — 전화 전달 게임

RNN은 교실에서 귓속말로 한 줄 전달하는 게임과 비슷하다.  
앞사람이 말한 “도서관에서 빌린 책”이 끝자리까지 가면 내용이 흐려질 수 있다.

Attention은 끝자리 학생이 **교실 전체를 동시에 바라보고**, “책”이라고 적힌 쪽을 직접 가리키는 것에 가깝다.

### 6. 직관적으로 이해하기 — CNN의 한계

#### 6.1 CNN이 문맥을 보는 방식

텍스트에 쓰는 **CNN(Convolutional Neural Network)**은 고정 크기 **커널(윈도우)**로 국소 패턴을 본다.

예: 커널 크기 3이면 대략 이웃 3토큰 패턴.

넓은 문맥을 보려면:

- 층을 깊게 쌓아 **receptive field(수용 영역)**를 키우거나
- dilated convolution 등으로 간격을 늘린다

#### 6.2 무엇이 부족한가?

1. **장거리를 보려면 깊이 또는 특수 설계가 필요하다**  
   거리 \(d\)를 연결하는 비용이 구조에 묶인다.

2. **위치마다 “가변적으로” 먼 곳을 보기 어렵다**  
   커널 가중치는 위치에 따라 내용 기반으로 자유롭게 “저쪽 토큰을 봐라”고 바뀌지 않는다(기본 conv 기준).

3. **언어의 비국소적 참조**에 덜 직접적이다  
   대명사 해소처럼 “문장 어디에 있는 그 명사”를 동적으로 고르는 문제에 Attention이 더 잘 맞는다.

CNN이 쓸모없다는 뜻이 아니다. 국소 특징 추출에는 강하다.  
다만 **현대 LLM의 문맥 혼합의 중심축**은 Attention이 되었다.

### 7. Attention이 주는 것

#### 7.1 직접 연결 (all-to-all)

Self-Attention에서는 (마스크 전제에 따라) 각 위치가 **다른 모든 위치**와 점수를 계산할 수 있다.

```text
토큰:  어제  도서관  에서  빌린  책  은  재미있었다
         ↓     ↓     ↓    ↓   ↓  ↓      ↓
      서로서로 유사도 점수 → Softmax 가중치 → 가중합
```

거리와 무관하게 **한 층에서 직접** 정보를 가져올 수 있다.  
이것이 장거리 의존에 강한 이유의 핵심이다.

#### 7.2 내용 기반 가중치

가중치는 고정 윈도우가 아니라, **토큰 내용(표현 벡터)**에 따라 달라진다.

- “재미있었다”는 “책”에 높은 가중치
- 다른 문맥에서는 “도서관”에 더 주목

같은 거리라도 문장에 따라 주목 대상이 바뀐다.

#### 7.3 병렬 계산

점수 행렬은 행렬곱으로 한 번에 계산할 수 있다 (37강).  
길이 \(T\)에 대해 RNN처럼 \(T\) 스텝을 직렬로 기다릴 필요가 적다.  
GPU와 잘 맞는다.

#### 7.4 대가 (미리 보기)

- 기본 Self-Attention 계산·메모리는 대략 \(O(T^2)\) 스케일 (52강)
- “미래 토큰을 보면 안 되는” LM에서는 **Causal Mask**가 필요 (40강)
- 한 종류의 주목만으로는 부족해 **Multi-Head**로 나눈다 (41강)

오늘은 대가보다 **필요성**이 우선이다.

### 8. 작은 숫자로 “정보 도달”만 비교하기

수학적 Attention은 아직 쓰지 않는다.  
대신 “몇 홉(hop) 만에 정보가 도착하는가”만 센다.

시퀀스 길이 \(T=8\). 위치 1의 정보가 위치 8에 필요하다고 하자.

| 구조 | 한 층에서 도달? | 대략적 경로 |
|---|---|---|
| RNN | 아니오 | 1→2→…→8 (7 hop) |
| CNN (커널 3) | 아니오 | 층을 쌓아 수용 영역 확대 |
| Self-Attention (풀) | 예 | 1↔8 직접 점수 |

이 표는 성능 보장이 아니라 **연결성** 이야기다.  
실제 품질은 학습·깊이·데이터에 달렸다. 그래도 “왜 Transformer가 언어에 끌려왔는지”의 출발점이다.

### 9. 코드로 감각만 잡기 (모의 가중 평균)

진짜 Q/K/V는 36강이다.  
여기서는 “주목 가중치로 가중합”이 문맥 혼합임을 보여주는 최소 코드만 본다.

```python
# lecture35_weighted_context.py
# Attention의 '결과 형태'만 체험: 가중치로 토큰 벡터를 섞는다.

import numpy as np

# 토큰 임베딩 (가짜). 행 = 토큰, 열 = 차원 d=3
# 0:나, 1:책, 2:을, 3:읽다
E = np.array(
    [
        [1.0, 0.0, 0.0],  # 나
        [0.0, 1.0, 0.0],  # 책
        [0.0, 0.0, 1.0],  # 을
        [0.2, 0.7, 0.1],  # 읽다
    ],
    dtype=np.float64,
)

# 위치 3("읽다")가 문맥을 모은다고 가정.
# 사람이 정한 가짜 주목 가중치 (합=1): 책에 많이 주목
weights = np.array([0.05, 0.75, 0.05, 0.15])

# 가중합 = Attention 출력의 핵심 형태
context = weights @ E  # shape (3,)
print("mixed context vector:", context)

# RNN식 '마지막 상태만' 쓰는 것과 비교하는 장난 예
rnn_like = E[-1]
print("last-token only:", rnn_like)
print("difference:", context - rnn_like)
```

요점: Attention의 출력은 본질적으로 **문맥 벡터 = 가중 평균**이다.  
가중치를 **데이터에 맞게 학습·계산**하는 장치가 Q/K/V다.

### 10. 실제 LLM에서는 어떻게 사용하는가

#### 10.1 Transformer 블록의 중심

GPT 계열은 Decoder-only Transformer를 깊게 쌓는다.  
각 층마다 Self-Attention이 토큰 표현을 섞고, FFN이 위치별로 비선형 변환을 한다.

#### 10.2 학습 목표와의 정합

Next-Token CE(34강)를 줄이려면, 현재 위치에 **알맞은 과거 정보**가 도착해야 한다.  
Attention은 그 “도착 경로”를 제공한다.

#### 10.3 해석 가능성 (예고)

Attention 가중치를 시각화하면 “모델이 어디를 보는지” 힌트를 얻을 수 있다 (51강).  
다만 가중치 = 완전한 설명은 아니므로 과해석은 금물이다.

#### 10.4 역사적 위치 (간단히)

- seq2seq + Attention (기계번역): 디코더가 인코더 열을 조회
- Transformer (2017): Attention만으로 병렬 학습이 강한 구조
- GPT: Causal Self-Attention으로 언어모델화

이 책은 역사 서술보다 **계산 가능한 이해**를 목표로 한다.

### 12. 자주 하는 실수

1. **Attention = Softmax라고만 생각한다**  
   Softmax는 점수를 가중치로 바꾸는 한 조각이다. 전체는 “점수 → 가중치 → 가중합”이다.

2. **RNN/CNN이 틀렸다고 단정한다**  
   한계를 이해하는 것이지, 모든 문제에서 쓸모없다는 뜻이 아니다.

3. **\(O(T^2)\)를 무시하고 “항상 최고”라고 본다**  
   긴 컨텍스트에서는 효율 문제가 크다 (52강, 5권 추론 최적화).

4. **오늘 수식을 전부 외우려 한다**  
   35강은 동기부여. 기호는 36강부터 하나씩.

5. **Embedding만으로 장거리 문맥이 해결된다고 생각한다**  
   Embedding은 토큰 고유 표현의 시작점이다. 문장 안 상호작용은 Attention/층이 담당한다.

### 13. 핵심 정리

- 언어에는 장거리 의존이 흔하고, 다음 토큰 예측에 먼 정보가 필요할 때가 많다.
- RNN은 순차 전달이라 멀수록 정보가 약해지기 쉽고 병렬화가 어렵다.
- CNN은 국소 윈도우에 강하지만, 장거리·동적 참조에는 층/설계 부담이 크다.
- Attention은 (마스크 내에서) 위치에 직접 연결 + 내용 기반 가중치 + 행렬곱 병렬화로 문맥을 섞는다.
- Attention 출력의 형태는 “토큰 벡터들의 가중 평균”이다.

### 14. 핵심 용어

| 용어 | 의미 |
|---|---|
| Attention | 위치에 대한 가중치를 만들어 정보를 가중합하는 메커니즘 |
| Long-range dependency | 멀리 떨어진 토큰 사이의 의존 관계 |
| RNN | 숨은 상태를 순차로 전달하는 신경망 |
| CNN (텍스트) | 고정 윈도우로 국소 패턴을 보는 신경망 |
| Receptive field | 한 출력이 볼 수 있는 입력 범위 |
| Self-Attention | 같은 시퀀스 안에서 서로가 서로를 조회 |
| Context vector | 가중합으로 만든 문맥 표현 |
| Parallelism | 순차 의존 없이 동시에 계산할 수 있는 성질 |

### 16. 다음 강의와 연결

“가중 평균으로 문맥을 섞는다”는 그림은 그렸다.  
남은 질문은 세 가지다.

1. **무엇과 무엇의 유사도로** 가중치를 만드는가?
2. **어떤 벡터를** 가중합하는가?
3. 그 벡터들은 **어디서 오는가?**

다음 **제36강. Query, Key, Value**에서 이 역할을 나누는 표준 해답 — **Q, K, V** — 를 도입한다.

> 왜 필요한지 알았으면, 이제 주목의 세 가지 역할부터 이름을 붙이자.

---

### 부록 A. 같은 문장을 세 구조로 “읽기”

문장: `그 / 학생이 / 어제 / 읽은 / 책은 / 두껍다`

| 구조 | 위치 “두껍다”가 “책”에 도달하는 방식 |
|---|---|
| RNN | 상태를 왼→오로 여러 번 전달 |
| CNN (작은 커널) | 층을 쌓아 수용 영역을 “책”까지 확장 |
| Attention | 한 층에서 “책”과 직접 점수·가중합 |

이 표는 성능 순위표가 아니다. **정보 경로의 형태** 비교다.

### 부록 B. “요약 벡터 하나”의 병목

RNN의 \(h_t\)는 과거 전체를 고정 길이에 압축한다.  
필요한 정보가 희귀하면 압축 과정에서 사라지기 쉽다.

Attention은 (마스크 범위 안에서) **원본 위치의 Value를 다시 조회**할 수 있다.  
“요약만 들고 가기”와 “필요할 때 다시 펼쳐 보기”의 차이다.

### 부록 C. 기계번역에서 온 직관 (짧게)

초창적 seq2seq는 인코더가 문장 끝 상태 하나에 의미를 몰아넣었다.  
Attention은 디코더가 인코더의 **모든 시점**을 조회하게 해 병목을 풀었다.  
Self-Attention은 그 아이디어를 **한 시퀀스 안**에도 적용한 것이다.

### 부록 D. 연산 비용과 필요성의 균형

Attention이 필요하다고 해서 무조건 \(T^2\)를 감수하라는 뜻은 아니다.  
긴 컨텍스트에서는 근사·희소·선형 Attention 등이 연구된다 (52강, 5권).  
그래도 “왜 기본형이 이 형태인가”를 아는 것이 우선이다.

### 부록 E. 실습 4 답

### 부록 F. 실습 2 답

### 부록 G. 다음 강을 위한 세 질문 (다시)

1. 가중치는 무엇과 무엇의 유사도로 만드는가? → Query·Key  
2. 가중합의 재료는 무엇인가? → Value  
3. 그 벡터는 어디서 오는가? → \(XW_Q, XW_K, XW_V\)

36강이 이 답을 정식화한다.

### 부록 H. 오해: “Attention만 있으면 된다”

원 논문 제목의 수사와 달리, 실제 Transformer에는 FFN·정규화·잔차·위치정보가 있다.  
오늘은 “문맥 혼합의 중심이 Attention”이라는 주장이지, “다른 부품이 없다”는 뜻이 아니다.
