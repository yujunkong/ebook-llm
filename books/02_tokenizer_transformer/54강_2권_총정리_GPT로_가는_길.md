# 2권. Tokenizer와 Transformer

## 제54강. 2권 총정리 — GPT로 가는 길

### 1. 이번 강의에서 배울 것

새로운 API를 많이 추가하지 않는다. 2권 전체(27~53강)를 **한 장의 GPT 입구 지도** 위에 다시 올려, “지금 할 수 있는 것”과 “3권에서 붙을 것”을 고정한다.

이 강의를 마치면 다음을 말할 수 있어야 한다.

- 텍스트가 토큰·임베딩·Attention·Block을 지나 Causal LM logit이 되기까지의 한 줄 파이프라인
- Mini Transformer 프로젝트가 증명한 능력 범위
- 스스로 점검할 체크리스트
- 다음 강의 **제55강. GPT란 무엇인가**로 넘어가기 전 준비물

### 2. 왜 총정리가 필요한가

2권은 속도가 빠르다. Tokenizer에서 시작해 Attention 전 과정, Block 조립, Mini Transformer, 복잡도·변형 개요까지 왔다. 각 강의를 통과해도 머리속에서는 조각으로 남을 수 있다.

총정리의 목적은 복습 시험이 아니라 **좌표 재정렬**이다.

```text
조각 지식
  → 하나의 Causal LM 파이프라인
    → 3권 GPT Pretraining이 꽂힐 소켓 확인
```

### 3. 2권이 답하려 한 질문

한 문장으로 압축하면 다음과 같다.

> 문자열을 토큰 ID 서열로 바꾸고, Causal Transformer 위에서 다음 토큰 분포를 계산·학습·생성할 수 있는가?

1권이 “엔진실”이었다면, 2권은 **언어가 드나드는 입출력 장치와 조향 장치(Attention)**를 장착한 단계다.

### 4. 개념 지도 — 2권 → GPT 경로

#### 4.1 전체 파이프라인

```text
텍스트
  → Tokenizer → token ids [B, T]
    → Token Embedding (+ Position)
      → Transformer Block × N   (Causal Self-Attention + FFN)
        → (final LN)
          → lm_head → logits [B, T, V]
            → Softmax / CE Loss / Generation
```

학습 시:

```text
배치 (x, y=시프트)
  → forward
    → CrossEntropy
      → backward
        → optimizer.step
          → (가끔) greedy/sample generate
```

이 그림이 곧 3권 Pretraining 루프의 축소판이다.

#### 4.2 강의별로 꽂히는 위치

| 2권 주제 | 대표 강 | GPT 경로에서의 위치 |
|---|---|---|
| 텍스트→숫자 | 27 | 데이터 파이프라인 입구 |
| Char/Word/Subword · BPE | 28~29 | 실전 tokenizer의 계보 |

| Softmax · Logit | 33 | 분포·디코딩 직전 |

표를 외울 필요는 없다. **막힐 때마다 어느 소켓을 다시 볼지** 찾는 용도다.

#### 4.3 수식 한 줄로 다시 쓰기

결합 분포의 인과 분해:

$$
P(x_1,\ldots,x_T)=\prod_{t=1}^{T} P(x_t\mid x_{<t})
$$

모델은 각 $t$에서 logit $z_t\in\mathbb{R}^{V}$를 만들고, Softmax로 $P(\cdot\mid x_{<t})$를 낸다. 학습은 배치 평균 Cross Entropy로 $\theta$를 갱신한다.

$$
\theta\leftarrow\theta-\eta\nabla_\theta L_{\mathrm{CE}}
$$

1권의 Gradient Descent 문장이, 이제 **토큰 단위 Loss** 위에 올라와 있다.

#### 4.4 코드 한 줄로 다시 쓰기

```python
logits = model(x)  # [B, T, V]
loss = F.cross_entropy(logits.view(-1, V), y.view(-1))
loss.backward()
optimizer.step()
```

생성:

```python
next_id = torch.argmax(logits[:, -1, :], dim=-1, keepdim=True)
```

3권에서도 뼈대는 같다. 바뀌는 것은 데이터 규모, 모델 폭·깊이, tokenizer, 로그·체크포인트 규율이다.

### 5. Mini Transformer가 증명한 것

제49~50강 프로젝트를 완료했다면 다음이 가능하다.

1. char(또는 동급) tokenizer로 텍스트↔ID
2. Causal Self-Attention Block 스택 forward
3. next-token CE 학습으로 loss 감소 관찰
4. greedy decode로 문자열 연장

아직 증명하지 않은 것(3권 이후):

- 대규모 코퍼스 Pretraining
- 좋은 일반화·벤치마크
- SFT·정렬(RLHF 등)
- 고성능 서빙(KV paging 등)

부족함이 실패가 아니다. **경계가 명확해야** 다음 권이 선명해진다.

### 6. 능력 체크리스트

건너뛰기 전에 스스로 표시한다.

#### Tokenizer

- [ ] 텍스트가 왜 연속 실수가 아니라 이산 토큰 ID가 되는지 설명한다
- [ ] Subword/BPE가 왜 등장했는지 한 문장으로 말한다
- [ ] vocab_size가 lm_head 차원과 같아야 함을 안다

#### Language Model 목표

- [ ] next-token prediction과 타깃 시프트를 그림으로 그린다
- [ ] logit과 Softmax·CE의 관계를 말한다
- [ ] causal mask가 커닝(미래 참조)을 막는다고 설명한다

#### Attention · Block

- [ ] Q, K, V 역할을 구분한다
- [ ] $[B,T,C]$ shape를 forward에서 추적한다
- [ ] MHA · LN · Residual · FFN을 Block 하나로 조립한다
- [ ] Decoder-only CLM 골격을 외우지 않고도 다시 그린다

#### 프로젝트

- [ ] `config.py` / `tokenizer.py` / `model.py` / `data.py` / `train.py` 역할을 말한다
- [ ] 한 배치 overfit 테스트로 구현을 검증한다
- [ ] greedy 생성에서 `block_size` crop과 `model.eval()`을 챙긴다

#### 규모 감각

- [ ] Attention $O(T^2)$와 KV cache 미리보기를 구분한다
- [ ] GQA/MQA · FlashAttention 아이디어 · MoE를 “압력→응답”으로 분류한다
- [ ] 벤치 수치를 모른 채 구조를 설명해도 된다고 느낀다

하나라도 비면 해당 강으로 짧게 돌아간다. 전부 정상이다.

### 7. 1권과의 연결 (짧은 재확인)

| 1권 | 2권에서의 재등장 |
|---|---|
| Tensor · matmul | QK·AV·FFN |
| Autograd · Module | Mini Transformer 학습 |
| DataLoader 감각 | 토큰 배치 `(x,y)` |
| Loss · Optimizer | CE + AdamW |
| 과적합 | 미니 텍스트 암기 vs val |

엔진은 1권에서 이미 켜져 있었다. 2권은 그 엔진에 **토큰과 Attention**을 연결했다.

### 8. 3권으로 넘어가는 다리

3권 제목은 **GPT Pretraining과 SFT**다. 첫 강의는 다음과 같다.

> **제55강. GPT란 무엇인가**

거기서 다룰 축(미리보기, 세부 아님):

- GPT라는 이름이 가리키는 **구조·목표·학습 단계**의 좌표
- 2권 Causal LM이 왜 GPT 이야기의 중심인지
- Pretraining 데이터가 미니 `input.txt`와 어떻게 다른지(규모·다양성)
- 이후 구현·학습 목표·생성으로 이어질 목차의 입구

2권을 마친 독자의 올바른 자세는 “챗봇을 완성했다”가 아니라 다음이다.

> Decoder-only Causal LM의 부품과 미니 학습 루프를 손에 넣었으니, 이제 그 이름을 GPT 맥락에서 다시 정의하고 규모를 키울 준비가 되었다.

### 9. 추천 재학습 경로 (막힐 때)

| 증상 | 돌아갈 강 |
|---|---|
| 토큰화가 흐리다 | 27~30 |
| Loss·logit이 흔들린다 | 32~34 |
| Attention 수식이 안 읽힌다 | 36~40 |
| 블록 조립이 안 된다 | 44~48 |
| 코드가 안 돌아간다 | 49~50 |
| 비용·약어가 두렵다 | 52~53 |

### 10. 핵심 정리

- 2권의 핵심은 Tokenizer + Causal Transformer로 next-token LM을 세우는 것이다.
- 주 shape 관례 `[B,T,C]` → logits `[B,T,V]`를 끝까지 유지한다.
- Mini Transformer는 그 파이프라인을 “학습·생성”까지 닫은 관문이다.
- $O(T^2)$와 KV·변형 개요는 이후 규모·서빙을 위한 경고등이다.
- 다음은 제55강에서 GPT라는 좌표를 정의하는 일이다.

### 11. 핵심 용어 (2권 최종 압축)

| 용어 | 한 줄 의미 |
|---|---|
| Tokenizer | 텍스트 ↔ 토큰 ID |
| Vocabulary | 토큰 집합과 크기 $V$ |
| Embedding | ID → $C$차원 벡터 |
| Causal Mask | 미래 토큰 차단 |
| Self-Attention | 서열 안 QKV 상호작용 |
| Multi-Head | 여러 투영으로 병렬 Attention |
| Transformer Block | Attn + FFN + Norm + Residual |
| Causal LM | Decoder-only next-token 모델 |
| lm_head | $C\to V$ logit 투영 |
| Weight tying | emb↔head 가중치 공유(선택) |
| Cross Entropy | next-token 학습 손실 |
| Greedy decoding | argmax로 토큰 연장 |
| KV cache (preview) | 생성 시 K/V 재사용 저장 |
| GQA/MQA (overview) | K/V 공유로 캐시 압력 완화 |
| FlashAttention (idea) | exact Attn의 IO-aware 구현 방향 |
| MoE (teaser) | 전문가 FFN 라우팅 |
