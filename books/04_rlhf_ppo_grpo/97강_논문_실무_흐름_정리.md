# 97강. 논문·실무 흐름 정리
## 이번 강에서 배우는 내용

- InstructGPT류 파이프라인을 “대표적 RLHF 스케치”로 설명한다
- DPO가 그 스케치의 어느 상자를 바꾸는지 말한다
- Reasoning / verifiable reward RL이 선호 RL과 어떻게 갈라지는지 말한다
- 논문 제목·연도를 나열하는 것과 설계 패턴을 구분한다
- 제98강 총정리로 넘어갈 한 장의 지도를 갖는다

## 왜 중요한가?
4권 후반에 이름（InstructGPT, DPO, GRPO, RLVR…）이 한꺼번에 쏟아지면, 학습자는 **연대기 암기**로 도망가기 쉽다. 현장은 연대기가 아니라 **신호·인프라·평가**로 방법을 고른다.

```text
잘못된 질문: 지금 무엇이 SOTA인가?
이 강의의 질문: 우리 신호는 선호인가 검증인가? 온라인이 가능한가?
```

논문 제목을 나열하지 않고도, 79~96강이 꽂히는 **소켓 지도**를 손에 넣는 것이 목표다.

## 수식 한 장으로 줄기를 고정하기
### 9.1 InstructGPT류（개념）

$$

\max_\theta\;
\mathbb{E}_{y\sim\pi_\theta}\big[r_\phi(x,y)\big]
-
\beta\,\mathrm{KL}\big(\pi_\theta\|\pi_{\mathrm{ref}}\big)

$$

$r_\phi$는 선호에서 학습한 RM. 최적화 엔진은 흔히 PPO clip（제87강）.

### 9.2 DPO류（개념）

Bradley-Terry와 KL-제약 최적 정책의 연결을 압축하면, 선호 쌍 $(y_w,y_l)$에 대해

$$

L_{\mathrm{DPO}}
=
-\log\sigma\Big(
\beta\big[
\log\tfrac{\pi_\theta(y_w\mid x)}{\pi_{\mathrm{ref}}(y_w\mid x)}
-
\log\tfrac{\pi_\theta(y_l\mid x)}{\pi_{\mathrm{ref}}(y_l\mid x)}
\big]
\Big)

$$

**사실:** 명시 RM 학습·온라인 롤아웃 루프를 **우회할 수 있는** 형태다.  
**해석:** “인프라가 싼 선호 정렬” 후보.  
**비주장:** 모든 상황에서 대체.

### 9.3 RLVR / Reasoning（개념）

$$

r=V(x,a)
\quad\text{또는}\quad
r=\sum_k r_k^{\mathrm{process}}

$$

정책 경사는 동일 계열:

$$

\nabla_\theta \propto \mathbb{E}\big[(r-b)\nabla\log\pi_\theta(y\mid x)\big]

$$

신호가 바뀌면 실패 모드도 바뀐다（제94·96강）.

### 9.4 한눈에 대조

| 줄기 | 핵심 기호 | 온라인 롤아웃 | 대표 실패 |
|---|---|---|---|
| RM+PPO | $r_\phi$, $\rho$, clip | 있음 | RM hacking |
| DPO | $\beta$, $\pi/\pi_{\mathrm{ref}}$ | 보통 없음 | 데이터 hacking |
| RLVR | $V$, pass@k | 있음（흔함） | verifier hacking |

## 논문 초록을 읽는 90초 템플릿
새 논문을 펼치면 다음만 먼저 적는다.

```text
1. Signal:     preference | verifier | mix | other
2. Offline?:   pairs only | on-policy rollouts
3. Reference:  KL explicit | inside loss | none stated
4. Algorithm:  PPO / DPO / GRPO / other (이름보다 역할)
5. Eval:       win-rate / pass@k / human / judge
6. Claim type: 사실(방법) vs 해석(의의) 분리
```

제95강 미니 프로젝트 report의 필드와 의도적으로 닮게 만든다. **손구현이 논문 읽기 근육**이 된다.

## 실무 안티패턴（문헌 과신）
1. “그 논문 figure의 막대가 우리 도메인 성능”  
2. “이름이 같으면 하이퍼파라미터도 같다”  
3. “DPO했으면 RLHF 실패 모드가 사라진다”  
4. “reasoning RL이면 선호 데이터가 필요 없다”（안전·문체는 남음）  
5. “커리큘럼 순서 = 발표 연도 순서”

## 읽는 규율 — 사실 vs 해석
이 강의의 모든 굵직한 주장 옆에 라벨을 붙인다.

| 라벨 | 의미 |
|---|---|
| **사실** | 공개된 방법의 구조·수식·구성 요소처럼, 재현 가능한 서술 |
| **해석** | “현장이 이렇게 많이 간다”, “개념적으로 이렇게 이어진다”처럼 단순화·교육용 정리 |
| **비주장** | 이 책이 의도적으로 단정하지 않는 것（최초성, SOTA, 내부 미공개 파이프라인） |

혼동하면 커리큘럼이 **가짜 역사**가 된다.

## 개념적 큰 줄기（교육용 지도）
```text
[3권] Pretrain → SFT
         │
         ▼
[4권·줄기 A] Preference data → (RM) → RL (often PPO-like) → aligned policy
         │                         ↘
         │                          DPO-like: preference → policy (no explicit RM)
         ▼
[4권·줄기 B] Verifiable tasks → outcome/process reward → RLVR / reasoning RL
```

**해석:** 많은 실무·해설이 위 순서로 “이야기를 만든다”.  
**사실:** 실제 조직·논문은 순서를 섞고, 단계를 건너뛰고, 이름을 다르게 붙인다.  
**비주장:** 위 화살표가 유일한 역사적 경로라는 주장.

## InstructGPT류 RLHF 스케치
### 3.1 상자 다이어그램

공개 InstructGPT 계열 서술에서 흔히 강조되는 단계（교육용 압축）:

```text
1) SFT on demonstrations
2) Train RM on comparisons (preferences)
3) Optimize policy against RM with RL (+ KL to reference)
```

**사실:** “데모 지도 → 비교로 보상 모델 → 보상 최대화 RL”이라는 **구성 요소 세트**가 이 계열 서술의 핵심이다.  
**사실:** RL 단계에 PPO류 알고리즘과 참조 정책 대비 KL 제약이 자주 등장한다（제87~89강）.  
**해석:** 이를 “현대 LLM 정렬의 기본형”으로 가르치는 것은 교육적 선택이다.  
**비주장:** 모든 상용 모델이 이 세 단계를 동일하게 수행한다.

### 3.2 각 상자가 푸는 문제

| 단계 | 입력 | 출력 | 남는 빈칸 |
|---|---|---|---|
| SFT | 示范 응답 | 형식·준수 초기 정책 | 동등 좋은 답의 순위 |
| RM | 선호 쌍 | 스칼라 $r_\phi$ | 대리 목표·해킹（96） |
| RL | 롤아웃+$r$ | $\pi_\theta$ | 분산·KL·비용 |

제86강 RLHF 전체 구조가 이 표의 상세판이다.

### 3.3 실무에서 무거운 점

문헌 다이어그램보다 현장이 더 힘들어하는 것:

1. 선호 데이터 품질·지침 일관성
2. RM 재학습 주기와 OOD
3. 온라인 롤아웃 인프라（생성·보상·학습 루프）
4. 안전·유용성 다축 회귀

**해석:** “PPO 수식을 외우는 것”보다 위 네 가지가 일정·비용을 지배하는 경우가 많다.

## DPO — 어느 상자를 접었나
### 4.1 개념적 위치

DPO（및 유사 직접 선호 최적화）의 교육용 한 줄:

> 선호 쌍에서 **암시적 보상**과 정책 업데이트를 한 손실로 묶어, 명시적 RM+RL 루프를 우회한다.

제90~91강의 손실이 그 중심이다.

```text
Preference pairs
      │
      ├─ classic RLHF:  → RM → RL
      │
      └─ DPO-like:      → direct policy loss
```

**사실:** DPO 유도는 “Bradley-Terry + 최적 정책의 닫힌꼴” 같은 가정 위에, KL-제약 RL 목표와 연결되는 형태를 쓴다.  
**해석:** 실무에서 DPO류가 인기를 끈 이유 후보 — 구현·인프라가 RM+온라인 RL보다 단순한 경우가 많다.  
**비주장:** DPO가 RLHF를 대체해 사라지게 만들었다 / 항상 더 좋다.

### 4.2 남아 있는 것 / 사라진 것

| | 명시적 RM+PPO | DPO류 |
|---|---|---|
| 선호 데이터 | 필요 | 필요 |
| 보상 모델 학습 | 있음 | 보통 없음 |
| 온라인 샘플링 RL | 있음 | 오프라인 쌍에 가깝 |
| KL/참조 정책 | 흔히 명시 | 손실 안에 참조 로그비 |
| 해킹·편향 | RM·eval | 데이터·eval |

제96강에서 강조한 대로, **상자를 접어도 데이터 한계는 접히지 않는다.**

### 4.3 실무 변형（이름만）

문헌·코드베이스에는 IPO, KTO, ORPO, 기타 선호 선호 손실이 이어진다. 이 책 본문은 DPO를 **대표 좌표**로 둔다. 변종을 외울 필요는 없고, “선호→정책 직접” 가족임을 보면 충분하다.

**비주장:** 특정 변종이 표준이다.

## Reasoning RL / RLVR — 신호가 갈라지는 지점
### 5.1 줄기 B

```text
수학·코딩·논리 등
  → 검증기 V (유닛테스트, 정답 매칭, 실행기…)
    → outcome / process reward
      → policy gradient / GRPO-like group relative updates
```

**사실:** 보상을 인간 비교 대신（또는 추가로）**자동 검증**에서 얻는 설정이 가능하다. 제93~94강.  
**해석:** “reasoning 모델” 제품 서사는 긴 CoT + 검증 가능 과제 + RL을 묶어 설명하는 경우가 많다.  
**비주장:** 특정 연도의 특정 모델이 이 패러다임을 발명했다 / 유일한 경로다.

### 5.2 선호 RL과의 차이（재고정）

| | 선호 줄기 | 검증 줄기 |
|---|---|---|
| 질문 | 어느 답이 더 나은가 | 이 답이 맞는가（과정이 타당한가） |
| 라벨 | 인간/모델 비교 | 검증기·테스트 |
| 실패 | sycophancy, style hacking | 허위 CoT, verifier hacking |
| 겹침 | 설명 문체·안전은 선호가 남아야 함 | 정답만으로 친절·안전이 안 생김 |

실무 시스템은 두 줄기를 **혼합**하는 경우가 많다. 예: 정답 RL + 안전 선호/선호.

## GRPO·그룹 상대 비교의 위치
제92강 GRPO는 “완전히 새로운 정렬 철학”이라기보다, **같은 프롬프트에서 여러 샘플을 뽑아 상대 baseline을 쓰는 정책 최적화 설계**로 읽는 것이 이 책의 좌표다.

**사실:** 그룹 내 상대 비교로 advantage 추정 분산을 줄이려는 아이디어는 REINFORCE with baseline 계열과 맞닿는다.  
**해석:** reasoning·verifiable 설정에서 “문제당 다샘플”과 잘 맞물린다고 설명하는 경우가 많다.  
**비주장:** GRPO만이 reasoning RL의 정답 알고리즘이다.

PPO vs GRPO를 종교처럼 고르지 말고, **롤아웃·메모리·구현 복잡도·안정성** 트레이드오프로 본다.

## “연대기”를 절대 사실처럼 쓰지 않는 법
교육용으로 자주 보이는 한 줄:

```text
InstructGPT-like RLHF  →  DPO-like direct preference  →  Reasoning/verifiable RL
```

이것을 어떻게 말해야 하는가.

| 말투 | 평가 |
|---|---|
| “역사는 반드시 이 순서였다” | 과도한 단정（비권장） |
| “개념 복잡도·인프라 부담이 대략 이 방향으로 이야기되기 쉽다” | 해석（허용） |
| “구성 요소 A/B/C를 비교하면 이렇게 놓인다” | 사실·구조（권장） |

같은 시기에 여러 아이디어가 병렬로 등장하고, 산업계 내부 기법은 논문보다 앞서거나 늦게 공개된다. **커리큘럼 순서 ≠ 세계 연대기.**

## 논문을 읽을 때 체크리스트
새 정렬·reasoning 논문을 펼칠 때:

1. **신호**는 선호인가, 검증인가, 혼합인가?
2. **온라인 롤아웃**이 있는가, 오프라인 쌍만인가?
3. **참조 정책 / KL**을 어떻게 쓰는가?
4. **평가**는 자동 judge인가, 검증 통과율인가, 인간인가?
5. 보고된 개선이 **어느 분포**에서인가?（제96강 shift）
6. 저자가 **사실（방법）**과 **해석（의의）**을 섞지 않았는가?

제95강 미니 파이프라인은 1~3번을 몸으로 고정하는 장치였다.

## 실무 의사결정 트리（초안）
```text
데이터가 선호 쌍 중심인가?
  ├─ yes → 인프라가 온라인 RL을 감당하는가?
  │         ├─ no  → DPO류 / 오프라인 선호 최적화부터
  │         └─ yes → RM+PPO류 또는 하이브리드
  └─ no  → 검증 가능한가?
            ├─ yes → RLVR / outcome RL (± process)
            └─ no  → SFT·규칙·도구로 되돌리거나 라벨 설계부터
```

**해석:** 현장의 첫 질문은 종종 “어느 논문이 최신인가”가 아니라 “우리 신호가 무엇인가”다.

## 수식 보강 — 논문→실무 체크
논문의 기호를 현장으로 옮길 때 최소 순서:

```text
1) 목적함수（무엇을 max/min 하는가）
2) 데이터 계약（쌍인가, 롤아웃인가, 검증기인가）
3) 안정장치（clip ε, KL β, 그룹 크기 G）
4) 평가（자동 + 인간, 분포 명시）
```

기호가 같아도 마스킹·길이 정규화·토큰 평균 vs 합이 결과를 가른다. 제95강 toy와 프로덕션의 차이는 대부분 여기에 있다.

## PPO clip과 DPO β를 같은 지도에 놓기
PPO（제87강）:

$$

L^{\mathrm{CLIP}}
=
\mathbb{E}\big[
\min\big(\rho A,\;\mathrm{clip}(\rho,1-\epsilon,1+\epsilon)A\big)
\big]

$$

DPO의 $\beta$는 “참조로부터의 허용 이동”을 손실 안에서 조절하고, PPO의 $\epsilon$은 **한 업데이트의 비율 폭**을 자른다. 둘 다 trust-region 감각의 친척이지 동일 하이퍼파라미터가 아니다.

| 장치 | 막는 것 | 과도하면 |
|---|---|---|
| $\epsilon$（PPO） | 한 스텝 과대 비율 | 학습 정체 |
| $\beta$（KL/DPO） | 참조 이탈 | 개선 정체 |
| 그룹 $G$（GRPO） | 높은 분산 | 비용↑ |

## 논문 → 실무 수식 체크리스트

InstructGPT형:

$$
\mathrm{SFT}\rightarrow \mathrm{RM}:\ 
L_{\mathrm{RM}}=-\log\sigma(r_w-r_l)
\rightarrow
\mathrm{RL}:\ 
\max\,\mathbb{E}[r]-\beta\mathrm{KL}
$$

DPO형 (RM 생략):

$$
L_{\mathrm{DPO}}=-\log\sigma\Bigl(\beta\log\frac{\pi(y_w|x)}{\pi_{\mathrm{ref}}(y_w|x)}-\beta\log\frac{\pi(y_l|x)}{\pi_{\mathrm{ref}}(y_l|x)}\Bigr)
$$

### 실무에서 빠뜨리기 쉬운 항

1. 응답 토큰 마스킹
2. length normalization
3. reference 모델 freeze
4. 평가 분포 ≠ 학습 선호 분포

## 실습 — BT / DPO 로스 스케치

```python
import torch
import torch.nn.functional as F

# Bradley-Terry RM
r_w, r_l = torch.tensor(1.2), torch.tensor(0.3)
loss_rm = -F.logsigmoid(r_w - r_l)

# DPO-like (logprob 차이)
beta = 0.1
logp_w, logp_l = torch.tensor(-2.0), torch.tensor(-2.5)
logp_ref_w, logp_ref_l = torch.tensor(-2.1), torch.tensor(-2.2)
logit = beta * ((logp_w - logp_ref_w) - (logp_l - logp_ref_l))
loss_dpo = -F.logsigmoid(logit)
print(float(loss_rm), float(loss_dpo))
```

## LLM에서는 어디에 사용될까?
이 지도는 다음 대화에 바로 쓴다.

| 상황 | 지도에서 고를 가지 |
|---|---|
| 챗봇 톤·거부 정책 | 선호 줄기（DPO 또는 RM+RL） |
| 수학·코딩 정답률 | 검증 줄기（RLVR） |
| 둘 다 필요 | 혼합 + 다축 게이트（96） |
| 인프라가 빈약 | 오프라인 선호부터 |
| 그룹 샘플 여유 | GRPO류 baseline 검토 |

5권으로 넘어가면 같은 체크포인트가 **엔진·GPU·네트워크** 위에서 다시 측정된다. 방법 선택과 서빙 선택은 다른 표다（제112강）.

## 핵심 요약
- InstructGPT류는 SFT→RM→RL（+KL）구성의 **대표 스케치**다.
- DPO류는 명시적 RM+RL을 접어 선호를 정책에 직접 넣는 **가족**이다.
- Reasoning/RLVR은 선호가 아니라 **검증 신호**가 중심인 옆줄기（또는 혼합）다.
- 교육용 화살표 연대기는 **해석**이며, 절대 역사로 외우지 않는다.
- 논문을 볼 때는 신호·온라인성·평가 분포를 먼저 묻는다.

## 용어 사전
| 용어 | 한 줄 의미 |
|---|---|
| RLHF | 선호/보상으로 정책을 Reinforcement Learning하는 정렬 틀 |
| InstructGPT-like | SFT→RM→RL 스케치의 대표 좌표 |
| DPO-like | 선호에서 정책으로 가는 직접 손실 가족 |
| RLVR | 검증 가능 보상 RL |
| Online vs Offline | 학습 중 새 샘플 생성 여부 |
| Proxy reward | 진짜 목표를 대신하는 보상 |
